# Radiance 1.0 · работа с веб-интерфейсом

## Проверка исследования

1. Откройте сайт после запуска по [инструкции](DEPLOYMENT.md). Убедитесь, что модель готова.
2. Выберите несколько DICOM или один ZIP. Лимит — 256 МиБ суммарно; для отдельных файлов — до 1000 файлов. Архив выбирается отдельно от DICOM.
3. Нажмите «Начать проверку». Несколько DICOM отправляются по очереди, результаты появляются по мере готовности. Для ZIP результат приходит после завершения пакета. Прошедшее время не является прогнозом оставшегося времени.
4. В списке снимки сгруппированы по Study UID. Файлы без идентификатора показаны отдельно. Одинаковые имена не объединяются. Фильтры меняют только отображение.
5. Выберите снимок. Справа показаны применимые критерии; для отмеченных нарушений доступна справка «Что проверить». Это описание критерия по ТЗ, а не локализация нарушения на изображении.
6. Увеличьте снимок при необходимости. Яркость, контраст и инструкция по клавиатуре находятся в «Настройки изображения и управление». Изменения отображения не влияют на прогноз.
7. «Отметить просмотренным» сохраняет отметку только в текущей вкладке. Это не медицинское подтверждение и не исправление результата модели. «Следующее с замечанием» переходит к следующему непросмотренному снимку с замечанием.
8. Скачайте CSV и при необходимости откройте «Печатный отчёт». В диалоге браузера можно сохранить PDF. Отчёт включает все файлы пакета, превью при наличии, идентификаторы, версию модели и отметки просмотра.

На узком экране главное замечание расположено перед снимком. Кнопка «Список снимков» раскрывает список. После выбора файла список сворачивается, фокус переходит к замечанию.

## Ошибки и повтор

Ошибка отдельного DICOM не отменяет результаты остальных файлов. При обрыве запроса отдельного DICOM создаётся строка Failure с неизвестными полями, оставленными пустыми. Если целиком не удалось отправить ZIP, показывается ошибка запроса — состав неполученного результата не выдумывается.

«Повторить этот файл» использует исходный файл, сохранённый в памяти вкладки. Для ZIP веб-шлюз повторно принимает исходный архив и выбирает только нужный элемент по его позиции, включая случаи одинаковых имён. На инференс отправляется один выбранный элемент. Неисправный DICOM сам по себе от повторной отправки не исправится: для исправной копии начните новую проверку.

Повтор заменяет только соответствующую строку и её превью. Остальные результаты и отметки просмотра сохраняются. Повторная ошибка соединения не удаляет предыдущую строку. После повторного расчёта CSV отражает актуальные результаты; фильтры и отметки просмотра CSV не меняют.

Файлы, результаты и отметки не сохраняются между вкладками/перезагрузками. Перед новой проверкой или закрытием вкладки скачайте нужные материалы.

## Короткий сценарий защиты

Подготовьте локальный пакет из трёх случаев: снимок без замечаний модели, снимок с замечанием и повреждённый файл. Результаты подбираются для объяснения интерфейса; они не являются независимой оценкой качества модели.

1. Загрузите пакет и покажите реальный ход обработки.
2. Выберите снимок с замечанием. Покажите полный кадр, название критерия и «Что проверить».
3. Отметьте его просмотренным и покажите, что число просмотренных изменилось, а прогноз сохранился.
4. Откройте снимок без замечаний. Объясните, что это результат модели, а не гарантия корректности.
5. Откройте повреждённый файл: ошибка отделена от замечаний, успешные результаты сохранены.
6. Скачайте CSV и откройте печатный отчёт с версией 1.0.

Кнопка «Попробовать интерфейс» показывает только явно подписанные вымышленные записи без DICOM. Для защиты используйте разрешённые локальные снимки. Исходные медицинские данные и отчёты с UID не включаются в публичное демо автоматически.

## Проверки разработки

```bash
python -m web.check
# При работающем сайте на 127.0.0.1:8000 и установленном playwright-cli:
playwright-cli -s=web-workspace open http://127.0.0.1:8000
playwright-cli -s=web-workspace run-code --filename=web/check_browser.js
```

Проверка браузера использует вымышленные ответы API: несколько DICOM, одинаковые имена, обрыв связи, отдельный повтор DICOM/элемента ZIP, сохранность CSV и состава печатного отчёта. Настоящий инференс проверяется отдельно; тест не выдаёт фикстуры за прогнозы модели.

ML-модель и её пороги не менялись. Автоматические маски, метрические измерения, автокоррекция, DICOM SR и постоянный архив в эту итерацию не входят.
