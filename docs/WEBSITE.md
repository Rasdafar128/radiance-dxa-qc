# Сайт «DXA Контроль»

Развёрнутая версия: **[sefixnep.ru](https://sefixnep.ru)** — сайт с подключённой
моделью Radiance. Ниже описаны локальный запуск и самостоятельное развёртывание.
При проверке 25 сентября на публичном сайте оставался предыдущий интерфейс без
разметки. Описанный здесь текущий интерфейс пока проверен локально.

Лёгкое рабочее место: загрузка DICOM/ZIP, реальный вызов Radiance, просмотр снимка
рядом с критериями, список результатов, фильтры и CSV. Раздел «О модели» показывает проверенные метрики
и ограничения. «Попробовать интерфейс» открывает сохранённые результаты и снимки из «Для теста.zip» и работает без GPU.

## Два отдельных сервиса

| Компонент | Где работает | Требования |
|---|---|---|
| `web/` — сайт и шлюз | на VDS или локально | Python 3.12, без PyTorch; Docker по желанию |
| `src/solution` — Radiance API | GPU-сервер или локальный CPU | веса Radiance и ML-зависимости |

Браузер обращается только к веб-шлюзу. Адрес GPU задаётся на сервере через
`DXA_UPSTREAM_URL`, не передаётся в JavaScript. На vast.ai ML API слушает loopback;
для соединения VDS → GPU предусмотрен SSH-туннель.

## Локальный запуск

Если сайт и модель размещаются вместе, используйте готовый
[Docker Compose](DEPLOYMENT.md#сайт-и-модель-вместе). Команды ниже нужны для
отдельного веб-сервиса, в том числе VDS с удалённой GPU.

Из корня проекта, когда ML API уже доступен на `127.0.0.1:8080`:

```bash
python3.12 -m venv web/.venv
web/.venv/bin/pip install -r web/requirements.txt
DXA_UPSTREAM_URL=http://127.0.0.1:8080 web/.venv/bin/uvicorn web.app:app \
  --host 127.0.0.1 --port 8000 --no-access-log
```

Открыть [localhost:8000](http://127.0.0.1:8000). Даже без GPU доступны интерфейс,
описание модели и учебный пример; статус честно покажет отсутствие соединения.
Файлы шрифта хранятся в репозитории, CDN и внешние шрифтовые запросы не нужны.

Для предоставленного сервера:

```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -p 6947 -L 127.0.0.1:18081:127.0.0.1:18080 root@122.51.254.66
# В другом терминале:
DXA_UPSTREAM_URL=http://127.0.0.1:18081 web/.venv/bin/uvicorn web.app:app \
  --host 127.0.0.1 --port 8000 --no-access-log
```

Если прямой адрес недоступен, замените SSH-хост на `ssh6.vast.ai`, порт на `14805`.
Адрес/порты аренды могут измениться после пересоздания машины. Ключ SSH остаётся
у оператора; в образ и браузер он не копируется.

## Веб-контейнер

```bash
docker build -f web/Dockerfile -t radiance-web:1.0 .
# Docker Desktop: ML API/SSH-туннель работает на хосте.
docker run --rm --name lct26-web --read-only --tmpfs /tmp:rw,nosuid,size=600m \
  --cap-drop ALL --security-opt no-new-privileges \
  -p 127.0.0.1:8000:8000 \
  -e DXA_UPSTREAM_URL=http://host.docker.internal:18081 radiance-web:1.0
```

На Linux VDS с туннелем на loopback хоста:

```bash
docker run -d --name lct26-web --restart unless-stopped \
  --network host --read-only --tmpfs /tmp:rw,nosuid,size=600m \
  --cap-drop ALL --security-opt no-new-privileges \
  -e DXA_UPSTREAM_URL=http://127.0.0.1:18081 radiance-web:1.0 \
  uvicorn web.app:app --host 127.0.0.1 --port 8000 --no-access-log
```

Для постоянного VDS SSH-туннель нужно оформить отдельной службой с перезапуском,
а перед `127.0.0.1:8000` поставить HTTPS reverse proxy. Пример Caddy для собственного
домена и пароля (шаблон для самостоятельного развёртывания):

```caddyfile
{$DXA_DOMAIN} {
    basic_auth {
        reviewer {$DXA_PASSWORD_HASH}
    }
    reverse_proxy 127.0.0.1:8000
}
```

Синтаксис: [basic_auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth)
и [reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).
Хеш генерируется `caddy hash-password`; исходный пароль не записывается в Git.
Для первого закрытого демо достаточно общей учётной записи у reverse proxy.
Сам веб-шлюз не реализует аккаунты и открыт всем, кто может достичь его порта,
поэтому показанные команды публикуют его только на loopback.

## Поведение и границы

- Выбранный DICOM показан полным кадром, с сохранением пропорций пикселей.
  Доступны увеличение до 4× относительно окна, перемещение, яркость, контраст,
  сброс и полный экран в поддерживающих его браузерах. Клавиатура в области
  снимка: `+` / `−`, стрелки при увеличении, `0` для сброса.
- Стрелки над снимком переключают файлы текущего фильтра. Повреждённый файл
  показывает объяснение, а не изображение предыдущей строки. Пример использует
  три готовых снимка из «Для теста.zip» с результатами и разметкой Radiance.
- Превью строится шлюзом тем же декодером, что и ML-сервис: MONOCHROME1 учитывается,
  диапазон яркости соответствует сохранённой битности. Для браузера используется
  8-битный PNG, до 1024 px по длинной стороне; уменьшение отмечается над снимком,
  исходный размер доступен в «Данные файла и оценка».
  Это просмотр, не диагностический DICOM-вьюер. Настройки не меняют предсказания,
  CSV или исходный файл. Модель выдаёт классы и вероятности; веб-шлюз отдельно
  рассчитывает ориентиры и эвристическую подсветку включений по исходным пикселям.
  Слой можно скрыть; это не экспертная сегментация. [Работа с разметкой](WEB_WORKSPACE.md).
- PNG возвращаются в поле `previews` ответа `/api/analyze`, в исходном порядке
  строк. Одинаковые имена ZIP не объединяются. Суммарный лимит превью и наложений — 32 MiB
  до кодирования; превышение или ошибка превью не отменяет результат и CSV.
  Изображения остаются в памяти вкладки до новой проверки/перезагрузки.
- Один DICOM либо ZIP на запрос; отдельно выбранные DICOM браузер отправляет
  по очереди. Вложенные папки в ZIP допустимы.
- Ограничение загрузки 256 MiB; внутри ZIP — ограничения ML API: до 32 MiB на файл,
  512 MiB суммарно после распаковки, 10 000 элементов. [Входной контракт](USER_GUIDE.md).
- Сайт держит один запрос инференса на процесс. Если занят, новый запрос получает
  понятный ответ 503; очередь задач и многопользовательское масштабирование не реализованы.
- Один worker шлюза; таймаут модели 10 минут. `/health` проверяет шлюз,
  `/api/health` проверяет наличие Radiance на upstream.
- Временные файлы закрываются после ответа/ошибки. Истории и базы данных нет;
  результат хранится только в памяти открытой вкладки до новой проверки/перезагрузки.
- CSV содержит исходные UID; скачанный файл остаётся у пользователя. Файлы DICOM
  и подробные UID не отправляются в аналитику, её нет. Логи reverse proxy настраиваются
  отдельно при развёртывании; содержимое запросов логировать не нужно.
- «Есть замечания» — модель отметила нарушения; «Без замечаний модели» не является гарантией
  качества; «Не обработан» не превращается в отрицательное предсказание.
- На мобильном список снимков раскрывается из краткого результата над изображением.
  Численная оценка доступна в «Данные файла и оценка» на любом размере экрана.

## Проверка

```bash
web/.venv/bin/python -m web.check
```

Проверяется граница шлюза: упаковка DICOM, неизменный ZIP/CSV, лимиты, занятость,
ошибка upstream и защита статических путей; дополнительно — PNG из DICOM,
MONOCHROME1, одинаковые имена, точное соответствие строк и лимит превью.
Браузерные проверки исходной поставки проведены через
playwright-cli на 375 и 1440 px: пример, фильтры, ошибки, настоящий DICOM → CUDA → CSV.
Скриншоты локально в `.impeccable/review/`, отчёт — `artifacts/delivery-checks/web.json`.

Просмотр DICOM дополнительно проверен 19.09 на реальных снимках через CPU-модель
и веб-контейнер: увеличение, перемещение, яркость/контраст, полный экран, повторная
загрузка, CSV и ошибки. Агрегаты — `artifacts/viewer-checks/summary.json`,
снимки интерфейса — `.impeccable/review/viewer-*.png`.

Разметка и текущий интерфейс повторно проверены 25 сентября: [отчёт](RECHECK_2026-09-25.md).
