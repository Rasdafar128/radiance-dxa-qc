### Проверка модели и контейнера

```bash
python3 -m src.utils.prepare_model --verify-only
docker build --platform linux/amd64 -f docker/Dockerfile -t radiance:1.0-cpu .
python3 -m src.utils.check_delivery --image radiance:1.0-cpu --input data/test
# В тренировочной среде с полной выгрузкой:
HF_HUB_OFFLINE=1 python -m src.utils.check --device cuda
```

`check_delivery` запускает и удаляет только собственный временный контейнер.
Подключает входные данные read-only; веса и код берёт из образа. Без `--image`
проверяет подготовку комплекта на небольших синтетических файлах.

## Демо за несколько минут

1. Подготовить ZIP из трёх отладочных DICOM организаторов.
2. Запустить `./docker/run.sh cpu` или CUDA-вариант на подходящем Linux-хосте.
3. Показать `/health`: обе итоговые модели, устройство, состояние `ok`.
4. Отправить ZIP в `/batch`, открыть CSV: три строки, UID, область, качество,
   типы нарушений, `Success`, время.
5. Повторить с одним повреждённым файлом: для него отдельная строка `Failure`,
   исходные предсказания сохраняются. Не представлять отладочные файлы как тест качества.
6. Показать [карточку Radiance](../models/radiance/README.md): метрики, интервалы, независимый тест
   отсутствует, редкие классы и перенос на другие аппараты требуют проверки.
