# Radiance · финальное решение

Radiance проверяет качество DXA-снимков поясничного отдела и проксимального
отдела бедра. Вход — DICOM или ZIP; выход — результаты по каждому файлу и CSV.
Версия модели и поставки — **Radiance 1.0** (Git-тег `v1.0.0`).

## Состав

| Слой | Файлы | Ответственность |
|---|---|---|
| Интерфейс | `web/static/` | загрузка, просмотр DICOM с увеличением и настройками, критерии, CSV |
| Веб-шлюз | `web/app.py`, `web/previews.py`, `web/annotations.py` | временная загрузка, вызов закрытого API, PNG-превью и расчётные ориентиры |
| Инференс | `src/solution/` | DICOM, предобработка, модель, HTTP API и пакетный CLI |
| Контракт | `src/config.py` | точные имена колонок, областей и нарушений |
| Модель | `models/radiance/` | конфигурации, головы, пороги, метрики, SHA256 и лицензии |
| Развёртывание | `docker/`, `web/Dockerfile` | CPU/CUDA-образы и запуск обоих сервисов через Compose |
| Руководства | `docs/` | пользовательский контракт, установка, эксплуатация и проверка |
| Воспроизводимость | `research/`, `src/utils/` | обучение, аудит, журнал опытов и происхождение |
| Требования | `context/` | решения команды и документы организаторов |

Данные и рабочие артефакты остаются вне Git. Веса доступны в
[GitHub Release](https://github.com/sefixnep/LCT26/releases/tag/v1.0.0);
контейнер инференса включает их и работает без сети.

## Поток обработки

1. Браузер передаёт DICOM/ZIP веб-шлюзу. Шлюз принимает один пакет за раз,
   проверяет размер и доступность нужной версии Radiance.
2. API читает каждый файл независимо, сохраняет полный кадр и пропорции,
   учитывает битность и MONOCHROME1.
3. Замороженные DINOv3 Large (448) и MedImageInsight (512) получают признаки.
   Линейные головы оценивают область, пять нарушений и качество по области.
4. Вероятности энкодеров усредняются 0,5/0,5. Геометрические головы оценивают
   ось позвоночника и поле бедра. Оценка качества — среднее прямой головы и
   noisy-OR применимых критериев. Сохранённые пороги формируют итоговые типы
   и класс качества. Во время обработки модель не обучается.
5. API возвращает строку на каждый файл, включая дубли и ошибки. Интерфейс
   группирует снимки по анатомии и показывает выбранный кадр рядом с критериями;
   скачиваемый CSV сохраняет исходный порядок. Настройки просмотра не влияют на модель.

## Два варианта размещения

| Вариант | Запуск | Связь |
|---|---|---|
| Один сервер, CPU или NVIDIA GPU | [Docker Compose](DEPLOYMENT.md#сайт-и-модель-вместе) | веб-шлюз → `api:8080` во внутренней сети Docker |
| VDS с сайтом, отдельная GPU на vast.ai | [Сайт и SSH-туннель](WEBSITE.md) | браузер → HTTPS VDS → loopback-туннель → GPU API |

Порты по умолчанию доступны только локально. Для внешнего доступа перед сайтом
нужны домен, HTTPS и ограничение доступа; шаблон reverse proxy есть в руководстве.
Сайт размещён на [sefixnep.ru](https://sefixnep.ru); публикация текущих изменений
интерфейса пока не выполнена. [Состояние проверки](RECHECK_2026-09-25.md).
