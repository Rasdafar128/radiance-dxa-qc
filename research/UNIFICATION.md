# Объединение веток · Radiance 1.0

22.09.2026. Объединены `main` (`f8b1dfb`) и `dxa-qc` (`396f10b`).
Рабочий вход один: корневые CLI/API, Docker Compose и сайт Radiance.
Исходник второй ветки сохранён в `dxa-qc/` для воспроизведения исследований.

## Выбор модели

| Рецепт | F1 / AUC, основное разбиение | F1 / AUC, второе разбиение | Macro-F1 пяти целей, основное / второе |
|---|---|---|---|
| Исходный Radiance E5 | 0,613 / 0,805 | 0,577 / 0,754 | 0,460 / 0,421 |
| Геометрия оси/поля, вес 0,5, смешанная оценка качества | 0,636 / 0,821 | 0,613 / 0,773 | 0,531 / 0,500 |
| **Геометрия оси/поля, вес 1, смешанная оценка качества** | **0,676 / 0,821** | **0,621 / 0,780** | **0,604 / 0,524** |
| Геометрия всех критериев, вес 1, смешанная оценка качества | 0,527 / 0,799 | 0,542 / 0,759 | 0,402 / 0,389 |

Это лучший из проверенных рецептов по среднему F1 двух разбиений. Его прирост
относительно E5 составляет 0,062 / 0,044 F1 и 0,016 / 0,025 ROC-AUC.
При объединении одинакового названия «Некорректная укладка» для обеих областей
macro-F1 по четырём официальным названиям составляет 0,590 / 0,481.
Это другая агрегация, поэтому она не подменяет сравнение пяти целей в таблице.
Абсолютный максимум на неизвестном закрытом тесте не установлен.
Перебор воспроизводится командой `python research/compare_geometry.py`.
Все 28 результатов сравнения сохранены в [unification.json](results/unification.json).
На основном разбиении F1 оси вырос с 0,125 до 0,417, поля бедра — с 0,190 до 0,600.

Заявленные во второй ветке F1 0,663 / AUC 0,842 нельзя напрямую сравнивать с E5:
там усредняются десять повторов пяти фолдов, а пороги, калибровка и правило оси
подбираются по тем же OOF. Её `protocol_compare.py` тоже формирует другие фолды
отдельно для каждой области. В таблице выше использованы **точно те же**
249 изображений, метки и внешние/внутренние разделения исследований, что у E5.

## Итоговый рецепт

1. Общий декодер DICOM, полный кадр, исходная пиксельная сетка. Энкодеры DINOv3
   Large и MedImageInsight, их предобработка и головы сохранены.
2. Область определяется по среднему вероятностей энкодеров, без имён файлов.
3. Для оси позвоночника — два признака наклона яркостной центральной линии.
   Для поля бедра — высота кадра, латеральная/верхняя границы, расстояние ниже
   найденного малого вертела и индикатор выделенного бедра. Ориентация бедра
   определяется по пикселям данного кадра.
4. Две логистические головы: C=1, balanced, liblinear. Заполнение отсутствующих
   признаков средним и стандартизация обучаются **только на train**. На инференсе
   используются численные коэффициенты и сохранённые средние, без sklearn.
5. Геометрические головы заменяют вероятности только оси и поля бедра.
   Качество = 0,5 прямой региональной головы + 0,5 × (1 − произведение
   вероятностей отсутствия применимых нарушений).
6. Пороги типов выбираются по F1 внутреннего OOF, затем выбирается порог качества
   для пересечения с наличием типа. В итоговом CSV класс равен наличию нарушения.

Геометрия служит признаком классификатора. Её углы в пиксельной сетке и расстояния
**не выдаются за экспертные измерения**. Спорное предположение второй ветки об
изотропных 0,6 мм не переносится: расстояния хранятся в пикселях. Измеренное
наклонение яркостной линии не объявляется линией центров тел позвонков.

## Протокол и границы вывода

- 3 внешних групповых фолда, по 2 внутренних. Исследование целиком принадлежит
  одному фолду. 249 уникальных кадров из 100 исследований, 72 снимка с нарушениями.
- Каждый внешний прогноз получен моделью без этого исследования в train.
  Геометрические средние, масштабы, головы и пороги не видят внешний fold.
- Выбор **рецепта** из 14 вариантов на каждом из двух разбиений использует
  разработческие OOF. Второе разбиение — повторная проверка на тех же данных,
  а не независимая тестовая выборка. После него дополнительный перебор прекращён.
- 95% ДИ (bootstrap по исследованиям, 2000 повторов): F1 0,578–0,761,
  ROC-AUC 0,756–0,876, macro-F1 0,432–0,715. Интервалы не включают поиск рецепта.
- Один аппарат, неизвестная независимость пациентов, всего 7 положительных ROI.
  Перенос на другие аппараты и клиническая пригодность не установлены.

## Что нужно для хакатона

| Включено | Причина |
|---|---|
| Два энкодера и две геометрические головы | прирост на обоих разбиениях при прежнем комплекте крупных весов |
| Единый декодер, CLI/API, точный CSV, обработка ошибок и дублей | контракт задачи и автономная проверка |
| Существующий сайт с просмотром DICOM | демонстрация полного пользовательского сценария |
| Веса, хеши, лицензии, фиксированные зависимости | воспроизводимый запуск |

В поставку не включены второй сайт/API, дополнительные DINOv2/RAD-DINO,
контекст другого бедра, SAM, экспериментальные маски, DICOM SR и сбор обратной
связи. Для них нет подтверждённой пользы на текущем протоколе либо необходимости
в контракте сдачи. Исследовательский исходник сохранён, runtime его не импортирует.

В исходнике второй ветки исправлены выход ZIP в соседний каталог с совпадающим
префиксом, аналогичная проверка пути PNG и возврат заблокированного типа через
резервный выбор. Эти исправления не меняют итоговый классификатор Radiance.

## Воспроизведение

```bash
# Окружение обучения с torch 2.8.0 / torchvision 0.23.0:
pip install -r requirements-train.txt
python -m src.utils.train_geometry --parent artifacts/e5-blend --output artifacts/reproduced-unified
python -m src.utils.train_geometry --parent artifacts/e5-blend-split137 --output artifacts/reproduced-unified-secondary
python -m src.utils.check_geometry
python -m src.utils.check_validation_pixels --run artifacts/reproduced-unified --device cpu --probability-atol 0.0002
python -m src.utils.check --model models/radiance --device cpu
python -m web.check
python -m src.utils.prepare_model --verify-only
```

Нужны локальные исходные DICOM и артефакты E5. Восстановление E5 описано в
[TRAINING](TRAINING.md). Новый обучающий скрипт проверяет хеш каждого исходного
файла, уникальность кадров и целостность разделений, сохраняет фолды, головы,
внутренние прогнозы, OOF, версии библиотек и хеши исходников. Локальные данные,
прогнозы с UID и кэши не публикуются.

Проверки runtime и образов перечислены в [DELIVERY](../docs/DELIVERY.md).

На локальном ARM CPU вероятность может немного отличаться от исходного CUDA-кэша.
Проверка геометрии на исходных кадрах дала точное совпадение. Для проверки OOF
из пикселей допуск вероятности указан явно (0,0002), совпадение области, классов
и всех типов нарушений требуется точное. Численная погрешность и ROC-AUC по
повторному инференсу сохраняются в `results/unification_pixels.json`.

Повтор исторического `check_final` на ARM не завершился: сначала строгий допуск
1e-10 остановил сравнение переобученной головы, а диагностические повторы выявили
расхождение до 1,86e-6. Исходные сохранённые головы не менялись. Условия успешного
исторического аудита не ослаблены в поставляемом скрипте, новый полный refit-аудит
не заявляется. При этом независимый инференс **249 исходных DICOM** через сохранённые
внешние модели новой версии воспроизвёл все классы/типы и обе главные метрики точно.
