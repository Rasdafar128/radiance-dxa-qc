# Завершающий ML-цикл

**Завершён 18.09.2026 на RTX 3080 20 ГБ. Итоговый выбор — E5, DINOv3 Large +
MedImageInsight; новый цикл не дал устойчивого преимущества над ним.** Проверены
10 дополнительных рецептов на исходных фолдах и три переноса повторной настройки
на split137. Финальный комплект — `artifacts/ml-final/`.

Протокол записан до новых результатов. Исходная точка: E5 DINOv3-L + MedImageInsight,
F1 0,613 / AUC 0,805 / macro-F1 0,460 на исходных разработческих OOF.
Данные, критерии и стороны не меняются. 249 изображений / 100 исследований.

## Предопределённые проверки

1. **Физическая геометрия:** DINOv3-L и MedImageInsight, прежние головы liblinear и
   quality gate. Полный кадр приводится к физическим пропорциям 1,05 мм по вертикали /
   0,60 мм по горизонтали, затем поля до прежнего разрешения. Проверить также прежний
   ансамбль 0,5/0,5 этих моделей. Контроли — соответствующие pixel_grid/gate-рецепты.
2. **Повторная внутренняя настройка:** исходные pixel_grid DINOv3-L и MedImageInsight,
   liblinear/gate, три двухчастных групповых разбиения с seeds 42,43,44. Все кандидаты
   голов оцениваются по объединённым повторным OOF; каждый снимок имеет одинаковую
   кратность. Сетка C, балансировки, порогов и правило ничьей прежние. Ансамбль 0,5/0,5
   настраивает пороги по таким же повторным прогнозам. Это изменение всей внутренней
   настройки голов/порогов, не только замена последнего порога.
3. **E4:** DINOv3-L, исходный pixel_grid, последние два блока. Начальные головы —
   L2 logistic C=0,1, balanced=True, liblinear, обученные только на текущем train.
   Никакие финальные головы предыдущих опытов не используются для инициализации.
   Masked BCE по восьми целям, train-only positive weights; AdamW wd=0,01,
   encoder LR {1e-5,3e-5}, головы 10×, batch 2 / effective 16, BF16, seed 42.
   До 20 эпох, patience 4 по внутренней validation loss. Начальное состояние (эпоха 0)
   также кандидат: при ухудшении допустимо оставить обученные головы без адаптации.
   LR выбирается по среднему best validation loss двух внутренних фолдов; число эпох
   для refit — округлённая медиана их лучших эпох. Пороги и quality gate — только
   по внутренним прогнозам выбранного LR. 15 запусков для внешних OOF + 5 для финала.
   Без геометрических аугментаций, изменения меток и полного размораживания.

Все внешние train/validation разделены по исследованиям. Обучаемые преобразования,
эпохи, регуляризация и пороги не используют внешний validation. Общая выборка уже
использована для исследования: это разработческие оценки, не независимый тест.

При улучшении F1 и AUC без явного ухудшения macro-F1 повторяем рецепт на заранее
выбранном split137. Для E4 допускается один дополнительный фиксированный ансамбль
0,5/0,5 с исходным MedImageInsight; его пороги настраиваются только внутри outer train.
Новых семейств энкодеров и расширения сеток в этом цикле нет.

готовые frozen-признаки и выполняется на CPU.

У DINOv3 пороги ROI остались 0,10 / 0,95 / 0,75: повторение не устраняет недостаток
положительных исследований. У ансамбля относительно E5 F1 изменился −0,003,

условия «растут F1 и AUC», а не заранее обещанный положительный результат.
Разбиение и сетки не выбираются по его будущим оценкам; проверяются оба энкодера
и прежнее арифметическое среднее. Дополнительных весов ансамбля не подбираем.
Согласованный frozen-контроль также усредняется с исходным MedImageInsight (0,5/0,5),
чтобы будущий результат E4+MedImageInsight можно было сравнить при одинаковых головах
и правиле объединения. Это контроль эффекта адаптации, без подбора весов ансамбля.

Пилот E4 прошёл две эпохи, точное сохранение/загрузку и искусственное прерывание
после первой эпохи. После восстановления состояния оптимизатора и генераторов
результат совпал с непрерывным запуском: признаки и численные головы идентичны.
Пиковая память пилота с несколькими загруженными моделями — 4,37 GiB; две эпохи
собственно обучения заняли 12,4 с без создания/загрузки моделей. Первичная проверка
манифеста исправлена до обучения: пустые строки сторон сравниваются после того же
CSV-преобразования, что и исходный сохранённый манифест; метки не менялись.

При переносе проверки MII на CPU сравнение кэша обнаружило 3 расхождения из 3072
признаков, максимум 1,0844e-5 при допуске 1e-5. Попытка остановлена до обучения голов;
каталог сохранён в `artifacts/research-cycle-3/failed-mii-cpu-cache`. Повтор успешно выполнен
на CUDA с исходным допуском. Это межустройственная численная разница, не изменение
данных или использование проверочных меток.

## Исправление сборки E4 до итоговой оценки

Согласованный frozen-контроль выявил ошибку: при присваивании DataFrame в таблицу
внутренних прогнозов порядок столбцов исходного словаря отличался от `HEADS`.
Обучение, функция потерь, контрольные точки и отдельные `jobs/*/predictions.csv`
сохранили правильные имена целей; ошибка затронула объединённую таблицу и её пороги.
Внешние метрики исходного `e4-dinov3` недействительны и исключены из сравнения.

Исправленный `e4-dinov3-v2` собирает внутренние прогнозы по именам голов из отдельных
запусков, повторно выбирает пороги только на внутренних данных и воспроизводит OOF
из тех же внешних весов/признаков. Веса, LR, эпохи, разбиения и метки не меняются.
Сохраняются исходный архив кода обучения, хеш родительского рецепта и исходник
`repair_finetune.py`; родитель помечается `invalid.json`. Исправление не выбиралось
по внешним метрикам. Будущие запуски `finetune.py` используют явный порядок `HEADS`.

Проверка протокола дополнена независимым восстановлением каждой именованной головы
из её коэффициентов и признаков, а затем сравнением объединённой таблицы с прогнозами
отдельных внутренних запусков. Старый переставленный вариант эту проверку не проходит.

## Воспроизведение

Для изменённого кода нужны новые каталоги опытов; сохранённые рецепты требуют
совпадения хешей. Исторические исходники каждого опыта лежат в его `source/`.
Текущий `finetune.py` сразу использует исправленный порядок голов.

```bash
python -m src.utils.check_cycle3
python -m src.utils.train --device cuda --backbone dinov3-large --weights artifacts/pretrained/dinov3-large --aspect physical --quality-gate --output artifacts/new-physical-dino
python -m src.utils.train --device cuda --backbone medimageinsight --weights artifacts/pretrained/medimageinsight --aspect physical --quality-gate --output artifacts/new-physical-mii
python -m src.utils.train_blend artifacts/new-physical-dino artifacts/new-physical-mii --output artifacts/new-physical-blend
python -m src.utils.train --device cuda --backbone dinov3-large --weights artifacts/pretrained/dinov3-large --features-from artifacts/e2-dinov3-large --inner-repeats 3 --quality-gate --output artifacts/new-repeated-dino
python -m src.utils.train --device cuda --backbone medimageinsight --weights artifacts/pretrained/medimageinsight --features-from artifacts/e1-medimageinsight --inner-repeats 3 --quality-gate --output artifacts/new-repeated-mii
python -m src.utils.train_blend artifacts/new-repeated-dino artifacts/new-repeated-mii --output artifacts/new-repeated-blend
python -m src.utils.train_fixed --output artifacts/new-frozen-control
python -m src.utils.finetune --pilot --output artifacts/new-pilot
python -m src.utils.finetune --output artifacts/new-finetune
python -m src.utils.check_protocol artifacts/new-finetune
HF_HUB_OFFLINE=1 python -m src.utils.check --device cuda --model artifacts/ml-final
```

Для чувствительности frozen-рецептов добавить `--outer-seed 137` и использовать
отдельные каталоги; затем собрать ансамбль из родителей того же разбиения.
Оценку закрытого конкурса заменять этими разработческими результатами нельзя.
Главный оставшийся ресурс — независимые размеченные исследования и экспертная
проверка редких целей/сторон, а не увеличение числа эпох на тех же примерах.
