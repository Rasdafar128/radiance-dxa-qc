## Что проверено на утечки и ошибки

- Внешние фолды не пересекаются по исследованиям; каждое изображение имеет
  ровно один внешний прогноз. Точные дубликаты пикселей удалены до обучения.
- Внутренние разбиения содержат только исследования внешней обучающей части.
- StandardScaler и LogisticRegression обучаются только на переданных обучающих
  строках. Внешние валидационные признаки не участвуют в fit или подборе порогов.
- Для двух энкодеров на обоих разбиениях повторно выполнены внутренний подбор
  параметров и обучение всех голов на каждой внешней обучающей части: **12
  наборов голов**. Параметры выбора и вероятности сохранённых голов совпали.
- Энкодеры заморожены: единый кэш признаков не обучается на всей выборке.
- Проверены SHA256 рецептов, манифестов, кэшей и сохранённых версий кода;
  состав E5 совпадает с родительскими моделями.
- Среднее внутренних вероятностей 0,5/0,5 и пороги E5 воспроизведены отдельно
  для каждого внешнего фолда и финального обучения. Внешние метки не использованы
  при выборе этих порогов.
- Внешние прогнозы воспроизведены из сохранённых голов. Метрики относятся к
  фактическому пути выдачи: выбор области → типы нарушений → фильтр качества.
- Финальные веса обучены на всей размеченной выборке и не используются для
  расчёта OOF. При переименовании сохранены веса, головы, предобработка и пороги;
  имя/версия и размещение истории обучения изменены. Связь с исходником —
  [radiance_provenance.json](results/radiance_provenance.json).
- Старый ошибочный результат E4 помечен недействительным. Исправление и
  отрицательные результаты сохранены в [журнале](ML_CYCLE3.md); E5 от него не зависит.

В ранних метаданных solver не записан явно: аудит нормализует отсутствие поля
к исходному `liblinear`. Численные параметры, прогнозы и выбор C воспроизведены;
это изменение формата метаданных, а не подмена результата.

## Дополнительная независимая сверка

Повторно проверены исходные архивы, Excel и все 499 тренировочных DICOM.
Папки исследований и `StudyInstanceUID` связаны взаимно однозначно; точных
дублей между исследованиями нет. Из 252 уникальных кадров в OOF вошли все
249 с известными критериями; исключены только три кадра без критериев.
Проверены соответствие меток Excel сохранённому манифесту и истинным меткам OOF,
полнота прогнозов и неизменность исходных файлов. Направление стороны бедра
при этом воспроизведено по принятой эвристике; это не экспертная проверка сторон.

F1/AUC/precision/recall пересчитаны непосредственно через sklearn, без функции
отчёта проекта. [Машинный отчёт](results/validation_review.json).

Дополнительно все **249 валидационных DICOM** пропущены через `Model.predict`
соответствующей модели внешнего фолда на CUDA: без кэша признаков и без модели,
обученной на всей выборке. Области, классы качества и все типы совпали с OOF;
разница вероятностей меньше 1e-12. [Проверка по пикселям](results/validation_pixels.json).
Повторный refit голов, внутренние пороги и bootstrap обоих разбиений воспроизвели
сохранённый [полный аудит](results/final_audit.json) без изменений.

## Чего проверка не доказывает

**Обнаруженных нарушений группового протокола E5 нет. Абсолютное отсутствие
любых утечек по этим данным утверждать нельзя.**

1. Исследования сгруппированы, но анонимизированные идентификаторы не позволяют
   подтвердить независимость пациентов. Разные исследования одного пациента
   потенциально могут оказаться в разных фолдах.
2. Архитектура и рецепт выбраны после сравнения разработческих OOF. Это источник
   оптимизма выбора модели. Второе разбиение использует те же данные и не становится
   независимым тестом. Интервалы не включают неопределённость поиска рецепта.
3. Точные дубликаты проверены; независимость всех визуально близких исследований
   и отсутствие пересечения с исходными предобучающими корпусами не доказаны.
4. Стороны парных снимков бедра и редкие метки требуют экспертной проверки.
   Всего 7 положительных ROI, 10 нарушений оси и 6 нарушений укладки позвоночника.
5. Нет внешней оценки на других аппаратах. Прототип не валидирован для
   клинического принятия решений.
6. Macro-F1 0,460 — среднее F1 пяти применимых пар «область / нарушение».
   Точная агрегация и перевод в конкурсные баллы организаторами не раскрыты;
   совпадение с их итоговым скором не обещается.

Переназначить часть уже использованных данных «новым holdout» недостаточно:
её метки уже повлияли на выбор рецепта. Для независимой итоговой оценки нужны
новые размеченные исследования с надёжными группами пациентов либо закрытый
тест организаторов. Оба имеющихся разбиения остаются разработческими.

## Воспроизведение

В тренировочной среде с сохранёнными артефактами, из корня репозитория:

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python -m src.utils.check_final \
  --output artifacts/delivery-checks/final_audit.json
python -m src.utils.check_validation --output artifacts/validation-review/independent.json
HF_HUB_OFFLINE=1 python -m src.utils.check_validation_pixels --device cuda
```

Проверки не изменяют модель и не выбирают новый рецепт. `check_final` повторяет
обучение голов из сохранённых признаков; `check_validation` сверяет исходные
данные и метрики; `check_validation_pixels` повторяет прогнозы из DICOM.
Отчёты содержат только агрегаты. Для запуска нужны тренировочная среда,
исходные данные и исследовательские артефакты, отсутствующие в образах поставки.
