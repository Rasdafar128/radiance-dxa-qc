# Рабочая документация

Здесь ведутся требования конкурса и решения команды. Исходные документы
организаторов находятся в `organizers/`, исследования — в [research](../research/README.md),
руководства по готовой поставке — в [docs](../docs/DELIVERY.md).
Корневой [README](../README.md) служит точкой входа и ссылается на эти разделы.

## Как поддерживать порядок

1. Обновлять факт в профильном документе. Из других рабочих документов ссылаться
   на него; краткий обзор в корневом README не должен превращаться в копию протокола.
2. Различать требование организатора, измеренный факт, выбранный план и гипотезу.
   Для требований указывать источник, для измерений — набор и способ воспроизведения.
3. Ответы и статусы вопросов вести только в QUESTIONS. После ответа обновлять
   затронутые требования или план, сохраняя источник подтверждения.
4. При реализации обновлять состояние и команды в корневом README. Запланированное
   не описывать как работающее; результаты сопровождать версией данных и рецептом опыта.
5. Журналы опытов, прогнозы и метрики сохранять с артефактами по правилам TEMPLATE;
   принятое по результатам опыта изменение подхода фиксировать в PLAN.
6. Описывать общие области ответственности, а не полное дерево проекта. Конкретные
   пути нужны только для запуска, контракта или ссылки на реализацию. При переносе
   раздела обновлять входящие ссылки и якоря.
