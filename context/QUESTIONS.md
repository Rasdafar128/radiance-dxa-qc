## Правила ведения

- Статусы и остаток вопроса ведём только здесь; требования — HACKATHON/CONTEST_RULES,
  внешние источники — RESEARCH, выбранный подход — PLAN, реализацию — TEMPLATE.
- Ответ сохраняем с источником и датой получения; отличаем текст ответа от собственной
  интерпретации и от проверки кода. Неполный ответ не закрывает весь вопрос.
- Закрытые записи переносим в конец, сохраняя ID и якоря. ID не переиспользуем.
- Опыты по качеству остаются в PLAN; результат модели не становится ответом эксперта.

## Требования задачи и разметка

### Q02 — Анатомические ориентиры и правила измерения

- **P1 · Частично отвечен, п. 6. Источник ответа:** эксперт через Антона Зеленского.
- **Подтверждено:** правило оси, сколиоза и источник примеров; отдельной инструкции
  разметчика нет. Определения — [HACKATHON §2](HACKATHON.md#2-таксономия-нарушений).
- **Осталось:** способ сведения центров при искривлении к одному углу, пограничная
  видимость Th12/структур, количественная трактовка малого вертела; сверка нужной редакции стандарта.
- **Решение:** использовать критерии ТЗ и нормальные примеры; сколиоз сам по себе не
  назначает нарушение. Не ждать несуществующую инструкцию для старта классификации.
- **Закрытие:** согласованные пограничные примеры и правила для автоматических измерений.

### Q03 — Официальный расчёт метрик

- **P1 · Частично отвечен: п. 9 первого и п. 2 дополнительного блока.**
- **Подтверждено:** две группы метрик — качество в целом и отдельные нарушения
  с macro-F1; вероятность используется для ROC-AUC, скрипта не будет. См. [HACKATHON §6](HACKATHON.md#6-как-оценивают).
- **Осталось:** формула объединения областей/групп, фильтрация изображений при оценке
  типов, учёт Failure, перевод в конкурсные баллы. Повторный ответ эти детали не раскрывает.
- **Решение:** отдельно показывать бинарное качество и типы по всей применимой выборке,
  общие и региональные результаты; не считать неизвестную формулу известной.
- **Закрытие:** описание оставшихся правил с примером; получение скрипта больше не условие.

### Q04 — Проверка стороны бедра

- **P2 · Подход подтверждён, п. 7; проверка реализации остаётся за командой.**
- **Подтверждено:** сторону определяют по изображению; тега нет и в закрытом тесте
  не будет. См. [HACKATHON §3.2](HACKATHON.md#32-сторона-бедра-берётся-из-пикселей).
- **Осталось:** независимая проверка знака именно нашего `side_score` и спорных случаев;
  ответ не содержит проверки всех 74 пар или исходного кода.
- **Решение:** текущая технически проверенная привязка с версией в манифесте;
  чувствительность к исключению пар с разными метками, без выбора стороны по F1.
- **Закрытие:** подтверждённый знак, аудит пар/одиночных кадров и список исправлений, если есть.

### Q13 — Противоречия итогов и типов нарушений

- **P2 · Приоритет целей разрешён п. 8; индивидуальные случаи не разбирались.**
- **Подтверждено:** отдельные критерии имеют приоритет над итогом; используется
  политика `criteria_v2` из [PLAN §2](PLAN.md#2-данные-и-разбиение--до-обучения).
- **Решение:** вернуть S006/S011/S035 в обучение по исходным критериям; бинарная цель
  равна OR флагов. J:L сохраняются только для аудита. Сколиоз сам по себе не означает ошибку (п. 6).
- **Осталось:** эксперт упомянул одну известную ошибку итога, аудит обнаружил три
  расхождения. Это не основание стереть находки или считать каждый случай подтверждённым.
  S079 остаётся наблюдением, без изменения метки.
- **Закрытие:** индивидуальный разбор при его получении; отсутствие разбора не блокирует
  использование критериев по уже полученной инструкции и документирование расхождений.

### Q01 — Определение ROI

- **Закрыт по смыслу целевого нарушения 18.09.2026, дополнительный ответ п. 4.**
  Корректность ROI — полная визуализация исследуемой зоны, правильный выбор поля
  сканирования; ориентиры — рис. 6. Определение — [HACKATHON §2](HACKATHON.md#2-таксономия-нарушений).
- **Решение:** классифицировать полноту поля по всему изображению; не искать отсутствующую
  сохранённую ROI аппарата и не планировать отдельное восстановление её маски.
- **Граница ответа:** точного алгоритма измерения отступов и координат примеров не дано.
  Это ограничение будущих геометрических измерений, а не блокер выбранной классификации.

### Q05 — Расхождения снимков и разметки

- **Закрыт по политике обработки 18.09.2026, дополнительный ответ п. 1.**
  Снимки с эндопротезами входят в задачу и возможны в тесте; оцениваются как обычное
  бедро. Сам протез не является нарушением и не служит основанием для Failure/нового класса.
- **Решение:** обычный инференс качества и типов; три кадра без критериев пока исключены
  из supervised-обучения и собственных метрик качества. Такое исключение разрешено на
  усмотрение команды; причина — неизвестные цели, а не наличие протеза.
- **Граница ответа:** индивидуальные метки не выданы. «Протез не нарушение» не делает
  снимок автоматически нормальным по полноте поля или позиционированию.
- **Основание:** [HACKATHON §3.3](HACKATHON.md#33-разметка-и-обнаруженные-расхождения).
