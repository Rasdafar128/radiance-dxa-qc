## 1. Решение: перенос готовых признаков и ограниченное дообучение

**Результат — локальный сервис для обеих областей и пяти типов нарушений:
DICOM → предобученный энкодер → классификаторы → таблица → пакетный API → контейнер.**
Медицинские предобученные модели входят в основной эксперимент, а не в дальний резерв.

| Компонент | Выбранный подход |
|---|---|
| Контроль работоспособности | EfficientNet-B0/ImageNet: быстро проверить весь путь от пикселей до сохранённых прогнозов |
| Основное сравнение | MedSigLIP, MedImageInsight, DINOv2 Large и DINOv3 Large с замороженными весами, одинаковыми целями и фолдами |
| Адаптация | один лучший доступный энкодер: сначала пространственные признаки, затем ограниченное дообучение |
| Головы | определение области; пять бинарных типов по применимости; отдельная общая оценка качества для каждой области |
| Общая цель | OR отдельных критериев C:I, имеющих приоритет над итогами по [Q13](QUESTIONS.md#q13--противоречия-итогов-и-типов-нарушений) |
| Выход | CSV: `quality_class` = есть выбранный тип; `quality_prob` = непрерывная оценка общей головы |
| Инференс | локальные веса, CUDA на доступном GPU; CPU проверяем как запасной режим без обещания той же скорости |

По уточнению пользователя 18.09.2026 оба DINO проверяются только в размере Large.
Предыдущий опыт пользователя в пользу DINOv2 — основание для парного сравнения,
а не установленное преимущество на этой выборке.

Основное ограничение — независимые наблюдения и достоверность целей. Дополнительные
эпохи не создадут новые исследования. Прежний произвольный предел «два улучшения B0»
заменён конечным набором содержательных гипотез и общим бюджетом вычислений.

## 2. Данные и разбиение — до обучения

Аудит завершён; экспертная верификация меток не завершена. Политика первого цикла:

| Предмет | Решение |
|---|---|
| Повторы | обучаться на уникальных пикселях; все изображения исследования держать в одной группе |
| Неизвестные цели | три кадра не участвуют в supervised-обучении и метриках качества из-за пустых флагов, а не из-за протезов; обычный инференс бедра по [Q05](QUESTIONS.md#q05--расхождения-снимков-и-разметки) |
| Расхождения итогов | S006/S011/S035 включены по исходным критериям C:I; J:L не меняют цели. Политика `criteria_v2` по ответу п. 8 и Q13 |
| Стороны бедра | подход по изображению подтверждён; знак нашего алгоритма остаётся проверкой [Q04](QUESTIONS.md#q04--проверка-стороны-бедра). При доступности эксперта первыми проверить 15 пар с разными метками и одиночные кадры |
| Внешнее разбиение | пересчитанные для `criteria_v2` три части из `candidate_folds_primary_3.csv`, по балансу меток без результатов моделей |
| Внутренняя настройка | два групповых фолда внутри каждого внешнего train; проверить оба класса для каждой цели |
| Фиксация | хеши манифеста и назначений, версия целей, числа позитивов/негативов, отсутствие пересечения групп и пикселей |

По этой политике используются **249 изображений из 100 исследований**; у редких целей
лишь шесть положительных исследований. Источник не исправляется: меняется приоритет
целей по ответу эксперта. Старые манифесты/фолды для 246 изображений не смешиваем с
`criteria_v2`; внешние части пересчитаны, внутренние ещё предстоит построить. Если внутренний
фолд не содержит оба класса цели, параметры этой цели фиксируем заранее и отмечаем
ограничение, а не ищем удачное разбиение по метрикам.

Повторных пациентов по анонимизированным данным исключить нельзя: группы исследований
— доступная защита от утечки, не доказанное разбиение по пациентам. При подтверждённом
изменении меток версионируем цели и повторяем зависимые опыты. Подгонка меток под F1 запрещена.
Q01 закрыт для выбранной постановки: ROI означает полноту поля сканирования.
По Q02 известно правило оси; для проверенных автоматических измерений пограничные
определения ещё неполны. Классификация не блокируется.
По Q12 новой/исправленной выгрузки не будет: оставшиеся расхождения документируем.
По Q03 известны порядок оценки и macro-F1 по типам, но не полная формула скоринга.

## 3. Предобработка

| Шаг | Поведение |
|---|---|
| Чтение | декодировать DICOM, проверить размерность/диапазон, учесть MONOCHROME1/2; невалидный синтаксис UID сам по себе не делает декодируемый кадр непригодным |
| Яркость | для текущих 8-битных изображений диапазон 0–255; без срезания светлых предметов перцентильной нормализацией |
| Поле | полный кадр с сохранением пропорций и дополнением до квадрата; без центрального кропа и удаления исходных чёрных границ |
| Размер | B0 — 224, MedSigLIP — 448, MedImageInsight — 512, DINOv2-L и DINOv3-L — 448; выбор DINO-размера является нашим рецептом |
| Каналы | серый канал повторить в RGB, применить нормализацию конкретных весов; не допускать повторного resize/crop внутри процессора |
| Аугментации | первый цикл без поворотов, кропов и зеркалирования: они могут изменить целевое нарушение или его интерпретацию |

Размеры и источники препроцессоров — [RESEARCH §3](../research/RESEARCH.md#3-кандидаты-бэкбонов).
Это сравнение готовых рецептов, не чистое сравнение архитектур при одинаковом разрешении.
Дополнение вместо штатного crop/растяжения явно записываем как собственное изменение.
Увеличение входа не создаёт исходных деталей, но позволяет меньше терять их при сжатии.
Один и тот же препроцессор используется в обучении, кэше и сервисе.

Классификатор первого цикла сохраняет пропорции исходной пиксельной сетки. Для будущих
геометрических измерений отдельно используем валидный PixelSpacing либо масштаб
аппарата из Q&A: `x_mm = x_px × sx`, `y_mm = y_px × sy`.
`tan θ_mm = (sx / sy) × tan θ_px`; при текущем масштабе 5° физического угла — примерно
8,7° пиксельного. Добавленные поля не считаются частью исходного изображения.

## 4. Основной эксперимент: замороженные энкодеры

| ID | Проверяемая гипотеза | Сравнение и результат |
|---|---|---|
| E0 | путь данных, обучения, сохранения и отчёта работает | B0 + линейные головы; реализован общий вложенный протокол ниже, без отдельного перебора архитектур |
| E1 | медицинский перенос полезнее общего ImageNet для этих нарушений | MedSigLIP и MedImageInsight против полного результата B0 на тех же внешних частях |
| E2 | визуальный претрейн общего домена сохраняет полезную структуру | DINOv2-L и DINOv3-L друг против друга и против медицинских энкодеров; выбор одного рецепта для адаптации |

В E1/E2 сохраняем кэш замороженных признаков; головы обучаются на CPU. Не загружаем
текстовые энкодеры для обычной классификации изображений. E0 не обязан оставаться
финальной моделью, но до появления подтверждённой замены даёт рабочий артефакт.

Для всех пяти энкодеров один протокол:

1. Проверить один прямой проход, доступ к нужным признакам, пиковую VRAM и локальное
   сохранение/загрузку. Зафиксировать точный checkpoint, ревизию, лицензию, версии среды.
2. Извлечь признаки в `eval`; стандартизацию обучать только на train соответствующего
   фолда. Не обучать PCA или другие преобразования на всей выборке.
3. Головы — L2-логистическая регрессия. Внутренняя сетка `C ∈ {0.01, 0.1, 1}`,
   `class_weight ∈ {None, balanced}`; область выбирается без подбора порога на внешних данных.
4. Типы: параметры и пороги выбирать по объединённым внутренним прогнозам и F1.
   Сетка порогов 0,05–0,95 с шагом 0,05; при равенстве брать больший порог, при равных
   результатах параметров — более сильную регуляризацию. Общие головы выбирать по ROC-AUC.
5. Переобучить выбранные головы на внешнем train и сохранить прогнозы его внешней части.
   Считать общие OOF-метрики, ошибки по исследованиям и цену инференса.

Преимущество конкретного классификатора в чужой статье не обосновывает перебор пяти
семейств голов у нас. На этом цикле не добавляем RF/MLP/SVM поверх каждого энкодера.
Проблема доступа к весам не останавливает остальные опыты: после двух часов активной
диагностики фиксируем блокер и пропускаем кандидата. Для MedImageInsight обязателен
**проверенный локальный артефакт**, а не зависимость от облачного endpoint.

## 5. Адаптация лучшего кандидата

| ID | Гипотеза | Один ограниченный опыт |
|---|---|---|
| E3 | глобальное усреднение теряет положение и маленькие детали | к глобальному вектору добавить средние признаки четырёх областей сетки 2×2 последней карты; те же линейные головы и внутренняя настройка |
| E4 | часть признаков нужно адаптировать к укладке и DXA | после обучения голов разморозить последние два блока выбранного энкодера и дообучить с малым шагом |
| E5 | два лучших рецепта исправляют разные ошибки | только при таком наблюдении проверить фиксированное среднее двух оценок; пороги настроить на внутренних прогнозах |

E3 — наша гипотеза по [источникам о локальных признаках](../research/RESEARCH.md#5-локальные-признаки).
Не требует масок или координат нарушения. Не переносим метку целого снимка на каждый
кроп. У MedImageInsight берём карту последней стадии, у ViT — пространственные токены
без служебных; если получить их без серьёзной переделки нельзя, E3 пропускаем.
Высокая размерность сетки может ухудшить результат — это проверка, не обещанное улучшение.

E4 использует общий энкодер, линейные головы и BCE с маской применимости/известности
целей; вклад нормируется по известным примерам каждой цели. Классовые веса вычисляются
только на train. Сначала обучаем головы при замороженном энкодере, затем размораживаем
два последних блока; для DaViT фиксируем соответствующие блоки последней стадии.
Начальная сетка шага энкодера `{1e-5, 3e-5}`, шаг голов в десять раз больше,
AdamW с `weight_decay=0.01`. Максимум 20 эпох адаптации, ранняя остановка после четырёх
эпох без улучшения внутренней validation loss. Эти значения — начальный рецепт,
не результат подбора на наших данных.

Для каждого внешнего фолда обе настройки E4 проверяются на двух внутренних фолдах.
Число эпох для переобучения внешнего train выбирается по внутренним остановкам
(округлённая медиана), пороги — по внутренним прогнозам. Затем один запуск на всём
внешнем train, без просмотра внешних меток для остановки. Итого **15 запусков**
(3 × (2 настройки × 2 внутренних фолда + 1 переобучение)), а не один запуск на всех
данных с последующим объявлением его точности валидацией.

Используем смешанную точность после проверки численной устойчивости, малый batch и
накопление градиента. Начать с batch 2, эффективный batch 16; увеличивать только после
замера VRAM. Не обещаем конкретное потребление памяти без запуска. Если E4 не помещается
по памяти или времени, сокращаем до одного размороженного блока по заранее записанной
причине и повторяем рецепт целиком. LoRA, полный unfreeze и ещё пять оптимизаторов
не становятся дополнительными осями поиска.

E3/E4 стартуют на лучшем доступном кандидате E1/E2; при победе B0 адаптируем его.
Выбор кандидата по разработческим OOF делает последующую оценку исследовательской —
ограничение явно отражаем в §7. Не собираем пять разных энкодеров по победителю каждой цели.
E5 допускается для максимум двух рецептов и при сохранённых внутренних прогнозах;
нет вложенных прогнозов — нет честной настройки ансамбля, опыт пропускаем.

## 6. Бюджет GPU и отсечение лишнего

**48 часов — основной цикл, до 72 часов — потолок с проверками устойчивости.**
Это лимиты окна доступности компьютера, не измеренное время моделей и не требование
держать GPU загруженным всё время. После извлечения признаков многие операции короткие
и выполняются на CPU. При хорошем результате разрешено закончить раньше.

| Окно от готовности среды | Работа | Условие выхода |
|---|---|---|
| 0–6 ч | среда, проверка данных и фолдов, E0, извлечение признаков E1/E2 | рабочие локальные веса, первый отчёт; недоступные кандидаты отмечены и пропущены |
| 6–18 ч | завершить E1/E2, ошибки по целям, E3 | таблица сравнения и выбранный кандидат для адаптации |
| 18–48 ч | E4, CPU-анализ результатов; E5 только при выполнении условий | решение по каждой гипотезе и готовые веса лучшего завершённого рецепта |
| 48–72 ч | второй seed обучения финалиста, проверка чувствительности к разбиению, резерв на сбой | отчёт устойчивости; никакой новой архитектуры или широкой сетки |

Перед длинным циклом измерить время одной эпохи и VRAM. Оценка E4 — время эпохи ×
максимум эпох × число запусков, плюс прогрев голов, валидация и сохранение. Если бюджет
не сходится, заранее сократить сетку до одного шага (9 запусков) или оставить frozen;
не обрывать неудобные фолды ради высокой средней метрики. Если закончена лишь часть
опыта, он не может заменить полный рецепт.

Второй seed повторяет выбранный рецепт на тех же внешних частях без новой архитектурной
селекции. Дополнительное сбалансированное разбиение строится независимо от прогнозов;
на нём сравниваются только финалист и его frozen-контроль с внутренней настройкой.
Это проверка зависимости от разбиения, не новый независимый тест. При нехватке времени
её сокращаем первой и честно указываем, что выполнено.

Для работы без присутствия человека достаточно последовательного запуска конечного
списка конфигураций, логов, сохранения после каждого фолда/эпохи и возобновления с
checkpoint. Правила — [TEMPLATE §4](TEMPLATE.md#4-артефакты-валидации).
Новая платформа управления экспериментами для этого не нужна. После каждого этапа
имеется пригодный результат, а сбой необязательного опыта не уничтожает предыдущий.

| Убрано из маршрута до сдачи | Почему |
|---|---|
| Поиск/скачивание внешних обучающих наборов, претрейн с нуля или собственный SSL на 249 кадрах | доступ, перенос домена и настройка съедят окно; готовые признаки проверяются быстрее |
| Полная сегментация SAM/nnU-Net, автокоррекция, измерительный оверлей | нет масок, согласованной геометрии и времени на отдельную оценку измерений |
| Генеративная синтетика, повороты/кропы с автоматически назначенными нарушениями | цели преобразований неизвестны; легко обучиться на артефактах генератора |
| Большие VLM/LLM, подбор текстовых промптов, десятки энкодеров и голов | не решают главный дефицит независимых меток и расширяют подбор по маленькому OOF |
| Стекинг, TTA, ансамбль всех фолдов по умолчанию | сложность и цена без установленного прироста; E5 достаточно для проверки простого ансамбля |
| Полноценный веб-интерфейс, DICOM SR, преждевременная ONNX/TensorRT-оптимизация | обязательный продукт — работающий пакетный API, отчёт и воспроизводимая поставка |

Экспертное время, если появится, направляем прежде всего на соответствие сторон,
противоречия меток и трактовку нарушений. Ручные измерения могут объяснить ошибки,
но отдельную геометрическую модель в этот цикл не добавляем.

## 7. Валидация и принятие решений

| Предмет | Правило |
|---|---|
| Основная оценка | объединённые внешние прогнозы трёх групповых фолдов для каждого полного рецепта |
| Настройка | обучаемые признаки, регуляризация, эпохи, пороги — только внутри соответствующего внешнего train |
| Главные показатели | сначала F1 бинарного качества и ROC-AUC по всем размеченным изображениям и по областям; затем macro-F1 пяти типов. Формула объединения этапов остаётся Q03 |
| Разбор | поклассовые F1, ROC-AUC, PR-AUC, чувствительность, специфичность, TP/FP/FN/TN; число положительных исследований |
| Маршрутизация | ошибка области входит в основной отчёт: пропущенные применимые цели дают отрицательные решения, а не исчезают из знаменателя |
| Сравнение | парные изменения на тех же исследованиях и 95% ДИ разности, а не сравнение двух несвязанных средних |
| Неопределённость | 2000 бутстрап-выборок исследований с возвращением; сохранять кратность и все снимки каждой выбранной группы |
| Неопределённые метрики | ROC-AUC при одном классе = NA, указывать число пригодных ресэмплов; F1 при нулевом знаменателе = 0 с явной отметкой |
| Неизвестные/спорные случаи | отдельный технический отчёт; не назначать им «норму» и не включать как размеченный тест |
| Финальные веса | после выбора рецепта внутренняя настройка на всей основной выборке, затем обучение на ней; сохранить препроцессор, веса, пороги и версии |

Не вводим выдуманный «значимый прирост 0,02»: один редкий случай может изменить метрику
сильнее. Сначала сравниваем бинарный F1 и ROC-AUC, затем macro-F1 типов и ошибки
редких целей. Не принимаем рост macro-F1 ценой явного ухудшения бинарного качества.
Проверяем устойчивость и ограничения инференса. Если показатели расходятся,
показываем компромисс и ошибки; при неубедительном выигрыше
сохраняем более простой/быстрый рецепт. Не выбираем модель по одной красивой общей цифре.

Все изображения уже просмотрены при аудите; OOF используется для разработки и выбора
моделей. Это **не независимая оценка выбранного победителя**. Бутстрап фиксированных
OOF не учитывает всю вариативность обучения и выбора архитектуры; широкие интервалы
не исчезают от увеличения числа эпох. Окончательная проверка — закрытый тест конкурса.
Общие оценки в [0;1] не объявляем калиброванными вероятностями.

Порядок экспертной оценки не доказывает, что типы считают только на корректно
распознанных плохих снимках: основной отчёт сохраняет все применимые изображения.
Для согласованного первого рецепта бинарный класс остаётся OR выбранных типов;
бинарный F1 считаем по этому реальному выходу, ROC-AUC — по `quality_prob`.
Отдельную бинарную голову оцениваем и на внутренних данных, но её собственный порог
не подменяет `quality_class` в отчёте и не скрывает расхождения с типами.

Если Q04 остаётся открытым, показать чувствительность метрик к исключению пар с
разными метками, не выбирать направление стороны по лучшему F1. Ошибки обработки
считать отдельно и раскрывать их влияние на локальные метрики; официальный порядок — Q03.

## 8. Выход и сервис

Контракт и комплектация — [HACKATHON §4–7](HACKATHON.md#4-формат-выхода), правила
реализации — [TEMPLATE](TEMPLATE.md). Достаточно `GET /health` и `POST /batch`:
ZIP с DICOM на входе, CSV на выходе. Упаковка начинается с E0, не ждёт победителя E4.

Приёмка:

- Все 499 обучающих и три отладочных файла дают строки; кэш одинаковых пикселей не
  удаляет исходные имена и UID. Ключ папки/Excel не подменяет StudyInstanceUID.
- Ошибочный DICOM рядом с валидным даёт Failure и не прерывает пакет. Повреждённый
  архив даёт описанную ошибку API, пути внутри архива не выходят за временный каталог.
- Ответы совпадают при перестановке файлов, одиночном запуске и после загрузки весов.
- Сборка из чистого клона сдаваемого публичного репозитория по одному скрипту;
  при сборке разрешена сеть, точные веса скачиваются по открытой ссылке без учётных
  записей команды; версии и хеши проверяются. Лицензия разрешает выбранное распространение.
  Отдельная передача Docker tar не требуется. Затем чистый Linux-запуск без сети
  и без подключения исходного репозитория. Измерены холодный запуск,
  память, полное время исследования; соблюдается лимит ≤ 3 минут на исследование.
- README описывает реальные команды/API; есть пользовательская инструкция, руководство
  развёртывания, рецепт обучения, презентация и демо-сценарий.

Для трёх кадров с протезами проверяем обычный успешный инференс бедра и сохранение
строк. Сам протез не запускает Failure, отдельный класс или автоматическое нарушение.
Наличие протеза также не означает норму по другим критериям. Без меток эти кадры,
как и отладочные, проверяют исполнение, а не точность классификации.
Высокая общая оценка без выбранного типа разбирается как расхождение; новый тип нарушения
не придумываем. Сдаём полный набор функций по условию, даже если улучшения модели не сработали.
