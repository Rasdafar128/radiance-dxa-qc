# Журнал второго цикла, 18.09.2026

## Протокол и порядок гипотез

249 размеченных изображений, 100 исследований, `criteria_v2`. Первичное разбиение
сохранено из первого цикла: три внешних фолда, два внутренних. Масштабирование,
выбор C/весов классов и порогов выполняются только внутри внешнего train. Метки,
стороны и состав выборки не менялись. Повторно используются только замороженные
признаки исходных предобученных энкодеров, а не обученные на всей выборке головы.

До новых результатов зафиксированы:

1. MedImageInsight: официальный визуальный DaViT с проекцией в 1024 признака,
   нормализация L2, полный кадр 512 с полями; исходные головы liblinear.
2. Отдельная замена liblinear на lbfgs у пяти энкодеров; прежняя сетка C, балансировки
   и порогов. У lbfgs свободный член не штрафуется.
3. DINOv3-L: CLS + средние четырёх квадратов пространственных токенов, 5120 признаков,
   без register-токенов; lbfgs. Контроль для этой гипотезы — global/lbfgs.
4. При улучшении — чувствительность к одному заранее выбранному разбиению seed 137,
   с повторным внутренним подбором. Это не новый независимый тест.

После отрицательного результата DINOv3/lbfgs и первого результата MedImageInsight
добавлена отдельная гипотеза: выдавать тип только при достаточной общей оценке качества.
Проверяются только DINOv3-L/global/liblinear и MedImageInsight/global/liblinear.
Для каждой области порог выбирается по F1 на внутренних OOF из сетки 0…0,95 с шагом
0,05, при равенстве — больший. Параметры самих голов остаются выбранными по прежним
правилам. Внешние прогнозы не используются для подбора этого порога.
`quality_class` по-прежнему равен наличию выданного типа; вероятности не изменяются.

Первоначальная запись и дополнение сохранены в `artifacts/research-cycle-2/`:
`preregister.md` и `gate-preregister.md`. Дополнительная гипотеза возникла после
просмотра разработческих результатов; скрытого независимого теста у нас нет.

## Почему F1 низкий

| Наблюдение | Что оно означает |
|---|---|
| Качество: 72 положительных изображения из 249 | Всегда выдавать нарушение дало бы F1 0,449; первый B0 лишь немного выше этого контроля |
| ROI бедра: 7 изображений / 6 исследований; ось: 10 изображений | Внутренние разбиения содержат очень мало положительных примеров, выбор порога нестабилен |
| DINOv2 ROI: AUC 0,881, F1 0,138 | Хороший порядок оценок не гарантирует удачный бинарный порог |
| DINOv3 ROI: 47 FP, пороги 0,10 / 0,75 / 0,85 | Ошибки редкой головы заметно портят общее качество через правило «любой тип» |
| DINOv3: 72 FP качества, из них 18 вызваны только ROI | Составная логика решения сама становится источником ложных тревог |
| В одном train доля ROI 0,039, средняя вероятность liblinear 0,404 | Штраф свободного члена и сильная регуляризация смещают оценки; это проверяемый механизм, но не единственная причина |
| После lbfgs ROI FP уменьшились 47 → 5, а FP укладки бедра выросли 33 → 60 | Исправление одного механизма не гарантирует улучшения всей системы |

Никакие примеры не удалялись и не переразмечались из-за ошибок моделей. Спорная
привязка сторон и редкие цели остаются ограничениями данных. Просмотр снимков не
заменяет экспертную верификацию.

## Чувствительность к разбиению

Seed 137 выбран до этих расчётов; все внутренние разбиения, параметры и пороги
рассчитаны заново. Признаки frozen-энкодеров можно использовать повторно, поскольку
они не обучались ни на одном снимке нашего набора. Это те же 100 исследований,
поэтому оценка остаётся разработческой, а не независимым тестом.

| Рецепт, seed 137 | F1 качества | AUC качества | Macro-F1 |
|---|---:|---:|---:|
| Исходный DINOv3-L | 0,502 | 0,720 | 0,435 |
| DINOv3-L + quality gate | 0,492 | 0,720 | 0,403 |
| MedImageInsight / liblinear | 0,544 | 0,727 | 0,478 |
| E5: среднее DINOv3-L + MedImageInsight | **0,577** | **0,754** | 0,421 |

Прирост одного quality gate не повторился. У E5 направление изменения F1 и AUC
сохранилось, но macro-F1 снизился. ΔF1 **+0,075**, парный 95% ДИ **−0,018…+0,164**;
ΔAUC **+0,035**, ДИ **−0,008…+0,079**; Δmacro-F1 **−0,015**, ДИ **−0,115…+0,067**.
Ни один из этих интервалов не доказывает устойчивое преимущество. Для ансамбля
дополнительно переобучены головы MedImageInsight на seed 137; это обязательный
участник того же рецепта, его внешние результаты не выбирали веса смешивания.

E5 — кандидат для следующей адаптации по общей оценке качества. Утверждения
«все нарушения улучшились» или «достигнуто качество на независимом тесте» не делаем.
Все исходные отрицательные опыты сохранены; разбиение не меняли после просмотра
его результата и наиболее удачное разбиение для отчёта не выбирали.

## Воспроизводимость и проверки

- `src.utils.fetch medimageinsight` скачивает официальный checkpoint и конфигурацию,
  проверяет зафиксированные SHA256. Файл с расширением `.pt` содержит safetensors;
  MLflow/pickle не исполняется. Код DaViT включён с лицензией Microsoft MIT.
- `src.utils.check_research` сравнивает подключённый DaViT с исходным кодом Microsoft:
  на контрольном снимке максимальная разница 0, 362 733 568 параметров.
  Пространственный pooling проверен независимым расчётом четырёх квадратов:
  максимальная разница 7,15e-7.
- `src.utils.check_protocol` проверяет хеши манифеста и исходников, уникальность пикселей,
  границы исследований и внутренних прогнозов, полноту OOF и сохранение выбранных порогов.
- `src.utils.diagnose` сохраняет число ошибок, пороги и средние обучающие вероятности;
  инструмент ничего не подбирает.
- Каждый опыт содержит `recipe.json`, архив фактических исходников, внутренние разбиения,
  прогнозы и параметры каждого фолда, OOF, метрики, финальные веса и версии среды.

Защита от утечки относится к доступным идентификаторам исследований. Пациентские поля
обезличены, поэтому независимость пациентов доказать нельзя. Выбор семейства модели
по OOF создаёт оптимизм разработческой оценки. Bootstrap исследований отражает
неопределённость фиксированных прогнозов и не учитывает поиск рецепта/переобучение.

## Команды

```bash
python -m src.utils.fetch medimageinsight
python -m src.utils.train --device cuda --backbone medimageinsight --weights artifacts/pretrained/medimageinsight --output artifacts/e1-medimageinsight
python -m src.utils.train --device cuda --backbone dinov3-large --weights artifacts/pretrained/dinov3-large --features-from artifacts/e2-dinov3-large --head-solver lbfgs --output artifacts/e2-dinov3-lbfgs
python -m src.utils.train --device cuda --backbone dinov3-large --weights artifacts/pretrained/dinov3-large --pooling spatial --head-solver lbfgs --output artifacts/e3-dinov3-spatial
python -m src.utils.train --device cuda --backbone dinov3-large --weights artifacts/pretrained/dinov3-large --features-from artifacts/e2-dinov3-large --quality-gate --output artifacts/e2-dinov3-gate
```

Для чувствительности добавить `--outer-seed 137` и новый `--output`.
Каталог уже проведённого опыта требует точного совпадения рецепта и исходников;
для повторения на изменённом коде нужен новый каталог либо исходники из архива опыта.


## Сквозное выполнение

E5 проверен на RTX 3080 20 GB с локальными весами и `HF_HUB_OFFLINE=1`:
502/502 успешных файлов, 81,2 с на весь пакет, 4,68 с на самое длинное исследование,
30,5 с отдельной холодной загрузки. Пройдены сохранение/загрузка, перестановка,
одиночный файл, дубли, MONOCHROME1, повреждённый DICOM, ZIP/API, протезы
и обнаружение испорченного файла весов. Время измерено при фоновых служебных задачах.

На CPU проверены три отладочных изображения: 103,7 с + 22,9 с загрузки,
классы и типы совпали с CUDA, максимальная разница вероятности 1,16e-5 при допуске 1e-4.
Это проверка совместимости CPU, не подтверждение времени полного пакета на CPU.
E0 повторно прошёл полный CPU-прогон: 502/502, 38,7 с.
Постоянный API и существующий Docker остаются на E0; новый ансамбль — локальный
артефакт `artifacts/e5-blend/final/`, запускаемый через тот же `Model.load` и batch/API.

```bash
python -m src.utils.train_blend artifacts/e2-dinov3-large artifacts/e1-medimageinsight --output artifacts/e5-blend
python -m src.utils.check_protocol artifacts/e5-blend
HF_HUB_OFFLINE=1 python -m src.utils.check --device cuda --model artifacts/e5-blend/final
```
