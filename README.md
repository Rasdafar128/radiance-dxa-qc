# ЛЦТ 2026 — контроль качества денситометрии (ДЗМ)

Сервис, который по DXA-исследованию в DICOM отвечает: пригодно ли оно для клинической
интерпретации, корректна ли укладка и область измерения, и какое именно нарушение
найдено. Сдаётся контейнером с пакетным API; приоритетные метрики — **F1 и ROC-AUC**.

Условие, таксономия нарушений, формат выхода и измерения по данным —
[context/HACKATHON.md](context/HACKATHON.md). Правила репозитория (что едет в контейнер,
контракт модели, как валидируем) — [context/TEMPLATE.md](context/TEMPLATE.md).

## Состояние

**Подготовка.** Модели нет. Разобраны данные: архивы распаковываются, 499 файлов
сворачиваются в 252 уникальных изображения, к каждому подставлена экспертная разметка
(249 из 252), область и сторона бедра определены. Дальше — бейзлайн.


распаковка даёт дерево из «????»), собирает таблицу и проверяет её состав ассертами.

## План

1. **Бейзлайн на область.** Классификация «позвоночник / бедро» по пикселям —
   обязательный пункт условия. Правило «300 столбцов = позвоночник» верно на всех 252
   изображениях и остаётся страховкой, но в сдачу должна ехать модель.
2. **Бинарный класс качества по каждой области** — сначала он, потому что промежуточная
   сдача требует минимум его и оценку разметки хотя бы для одной области.
3. **Типы нарушений** как мультилейбл внутри области: 3 класса для позвоночника,
   2 для бедра. Редкий класс — «Некорректная область интереса», 7 позитивов на 150
   изображений: отдельная модель там не выучится, нужен общий бэкбон и веса классов.
4. **Геометрия вместо обучения там, где критерий геометрический.** Наклон оси
   позвоночника (порог 5°) и отступы ROI (3 см / 2 см = 28,6 / 33,3 px) — это измерения
   по сегментации, а не абстрактный классификатор; такая ветка ещё и объяснима
   врачу, что прямо оценивается на питче.
5. **Контейнер и API** — не в конце. Пустой контейнер, который читает архив и выдаёт
   таблицу с заглушкой, стоит полдня и снимает весь риск сдачи.

Данных мало (252 изображения, 50/50 на уровне исследования), поэтому решения
принимаются по нескольким фолдам `GroupKFold` по исследованию, а числа подаются с
доверительными интервалами — см. [context/TEMPLATE.md §4](context/TEMPLATE.md).
