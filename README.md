# ЛЦТ 2026 — контроль качества денситометрии (ДЗМ)

Сервис, который по DXA-исследованию в DICOM отвечает: пригодно ли оно для клинической
интерпретации, корректна ли укладка и область измерения, и какое именно нарушение
найдено. Сдаётся контейнером с пакетным API; приоритетные метрики — **F1 и ROC-AUC**.

Условие, таксономия нарушений, формат выхода и измерения по данным —
[context/HACKATHON.md](context/HACKATHON.md). Источники, готовые веса с лицензиями и
разбор литературы — [context/RESEARCH.md](context/RESEARCH.md). Правила репозитория (что
едет в контейнер, контракт модели, как валидируем) — [context/TEMPLATE.md](context/TEMPLATE.md).

Разработка по регламенту идёт до **29 сентября 2026**, техэкспертиза до 14 октября,
защита 23 октября.

# Пайплайн

## Главное решение: измерять, а не угадывать

Три класса нарушений из пяти сформулированы в условии **как измерения**: наклон оси
до 5°, отступы ROI 3 см и 2 см, «на нижнем уровне визуализированы верхние края гребней
подвздошных костей, на верхнем — половина тела Th12». Четвёртый — ротация бедра — задан
через форму контура (малый вертел едва деформирует контур). Поэтому основа решения — не
классификатор на 252 картинках, а **сегментация анатомии → геометрические индексы в
миллиметрах и градусах → клинический порог**, с классификатором внешнего вида там, где
мерить нечего.

Три довода, почему так, а не «одна CNN на всё»:

| Довод | Числа |
|---|---|
| Классификации не на чем учиться | 252 изображения, у редкого класса **7 позитивов**; прямая CNN-классификация качества укладки в маммографии даёт ≈0.78 accuracy на **1631** снимке ([RESEARCH §3](context/RESEARCH.md)) |
| Так делают в QC рентгена | устоявшийся рецепт: анатомические точки → количественные индексы → правило или регрессия (Eur Radiol 2022, BJR 2024) |
| Это оценивается отдельно | «понимание клинической задачи», «обоснованность таксономии», питч. Ответ «наклон 6,9° при норме 5°» защищается, «сеть так решила» — нет |

```
DICOM
  │
  ├─0─ предобработка: изотропная сетка 0.6 мм, маска насыщения, нормализация
  │
  ├─1─ область (позвоночник/бедро) + сторона бедра
  │
  ├─2─ сегментация анатомии ──▶ индексы: угол оси, покрытие кадра,
  │                             выступ малого вертела, отступы ROI (мм)
  ├─3─ внешний вид: замороженные эмбеддинги + лёгкая голова
  │
  ├─4─ слияние (стекинг на OOF) + пороги по F1
  │
  └─5─ отчёт: xlsx/csv + оверлей с измерениями + DICOM SR
```

## 0. Предобработка

**Изотропный ресемплинг — первым делом.** Пиксель 1,05 мм по Y и 0,6 мм по X
(Q&A, вопрос 1), поэтому угол, посчитанный в пикселях, не равен углу в теле пациента:

```
tan θ_физ = (0.6 / 1.05) · tan θ_пикс = 0.571 · tan θ_пикс
```

Клинический порог **5° соответствует 8,7° в сырой пиксельной сетке** — ошибка в 1,75 раза
по тангенсу. Кадр ресемплится по Y в ×1,75 (билинейно) к сетке 0,6 × 0,6 мм; после этого
расстояние в пикселях переводится в миллиметры умножением на 0,6, а углы считаются честно.
Побочный выигрыш: снимки разных размеров становятся сопоставимыми.

Дальше по порядку:

| Шаг | Что и почему |
|---|---|
| Маска насыщения | **до** нормализации: `raw >= 250` при 8 битах — это металл и плотные артефакты. Главный признак класса «посторонние предметы»; после min-max признак теряется |
| Нормализация | перцентильная обрезка 1/99 + min-max на кадр; MONOCHROME1 инвертируется (в наборе его нет, но проверка стоит строку) |
| Два представления | полноразмерный изотропный кадр — для геометрии; квадратный паддинг + resize 448 — для эмбеддеров |
| Что **не** делаем | CLAHE по умолчанию выключен: он вытягивает фон и размывает насыщение металла. Включаем, только если замер на фолдах покажет выигрыш |

## 1. Область и сторона

Определение анатомической области — обязательный пункт условия и вход для всех следующих
стадий.

- **Модель**: замороженные эмбеддинги + логистическая регрессия, 2 класса. Задача
  тривиальная (позвоночник и бедро не похожи), ожидаем ~100% на фолдах.
- **Правило-страховка**: ширина кадра 300 px = позвоночник — верно на всех 252
  изображениях и на отладочном наборе. Расхождение модели и правила **логируется**: это
  бесплатный детектор того, что на проверке приехал другой аппарат.
- **Сторона бедра** (`side_score`, [src/utils/data.py](src/utils/data.py)) нужна только для
  сборки обучающих меток — в выходе сторона не различается. Гипотеза проверена на 74/74
  парах внутри исследований, но знак сверен лишь с двумя файлами отладочного набора:
  **пункт риска** ([HACKATHON §3.2](context/HACKATHON.md)).

## 2. Геометрическая ветка — ядро

### 2.1 Разметка масок: день работы, а не неделя

Размечаем **свои** 252 изображения в human-in-the-loop: SAM2/MedSAM2 с боксом-подсказкой
даёт маску, человек правит. По статье MedSAM2 время разметки падает с ~500 с до 65–74 с на
случай — на весь набор это один день. Внешние датасеты (AASCE, BUU-LSPINE) идут в
**претрейн** сегментатора, а не в обучение под наши метки: домен-гэп по текстуре большой,
переносится анатомия.

| Область | Маски |
|---|---|
| Позвоночник | тела позвонков (L1–L4 и нижний грудной), крылья подвздошных костей |
| Бедро | бедренная кость (головка, шейка, вертелы, диафиз), кости таза, седалищная кость |

### 2.2 Модель сегментации

**nnU-Net 2D**, 5 фолдов по исследованию: на медицинских наборах такого размера он сам
подбирает конфигурацию и не требует ручного подбора, а времени на подбор нет. Запасной
вариант, если он не потянет 252 изображения, — U-Net с замороженным энкодером DINOv3 и
лёгким декодером.

**Ключевые точки отдельной моделью не учим** — выводим из масок:

| Точка | Как получается |
|---|---|
| Верхние края гребней подвздошных костей | верхние точки маски таза слева и справа |
| Середина тела Th12 | центроид верхнего тела позвонка в маске |
| Большой / малый вертел | экстремумы кривизны контура бедренной кости на латеральной / медиальной стороне |
| Ось шейки бедра | главная ось компоненты «шейка» |

Отдельный keypoint-детектор добавляем, только если точки из масок окажутся нестабильными
на фолдах. Одна модель — одна точка отказа.

### 2.3 Индексы и критерии

Считается после §0, то есть в миллиметрах и градусах:

| Индекс | Как | Критерий |
|---|---|---|
| `spine_axis_deg` | угол линии через центроиды тел позвонков к вертикали | > 5° → «Не выравнена ось позвоночника» |
| `spine_top_margin_mm` | видна ли половина тела Th12 у верхнего края | не видна → «Некорректная укладка» |
| `spine_bottom_margin_mm` | видны ли верхние края гребней у нижнего края | не видны → «Некорректная укладка» |
| `lt_prominence` | отклонение медиального контура бедра от гладкой аппроксимации в зоне малого вертела, нормированное на ширину диафиза | **коридор**, а не порог: гладко → переротация, крупный выступ → недоротация, обе крайности → «Некорректная укладка» |
| `structures_visible` | есть ли в маске большой вертел, шейка, седалищная кость | чего-то нет → «Некорректная укладка» |
| `roi_margin_{top,bottom,left,right}_mm` | расстояние от bbox области измерения до краёв кадра | < 30 мм сверху/снизу, < 20 мм по бокам → «Некорректная область интереса» |

Пороги не забиваются константами из условия: константа — **начальное значение**, финальное
подбирается по F1 на OOF. Разметка делалась глазом эксперта, и его «3 см» и наши 30,0 мм
совпадут не идеально; расхождение само по себе диагностика.

### 2.4 Бесплатная проверка измерений

Геометрию можно проверить **без дополнительной разметки**: повернуть изображение на
известные δ = 3, 5, 7, 10° и проверить, что измеренный угол сдвинулся на δ; обрезать кадр
на известные k мм и проверить, что отступ упал на k. Ошибка измерения получается численно
и едет в презентацию как «точность измерения ±X°» — то, чего классификатор показать не
может. Эти же прогоны — регрессионный тест ветки ([TEMPLATE §6](context/TEMPLATE.md)).

## 3. Ветка внешнего вида

Для «посторонних предметов» геометрии нет, а общую «некорректную укладку» индексы
покрывают не полностью: в комментариях разметки есть перелом, эндопротез, люмбализация.
Здесь работает классификатор.

| Что | Решение | Почему |
|---|---|---|
| Бэкбоны | **MedImageInsight** (MIT), **MedSigLIP** (HAI-DEF, коммерческое разрешено), **DINOv3-B**; ImageNet-ConvNeXt как бейзлайн | лучшие в бенчмарке на 8 842 рентгенограммах: 93.1 / 91.0 mAUC; DINOv3 силён линейной пробой на малых наборах |
| Режим | **заморожены**, учим только голову | полное дообучение на 252 изображениях переобучается; остаётся контрольным опытом на 5 фолдах |
| Входы | два вида на изображение: весь кадр и тесный кроп по маске из §2 | кроп убирает фон и делает металл на теле заметнее |
| Голова | логистическая регрессия / линейный SVM, `class_weight=balanced`, своя на пару «область × класс» | у редкого класса 7 позитивов — линейная голова единственное, что там не переобучится |
| Ансамбль | усреднение рангов по бэкбонам и видам, TTA горизонтальным отражением для бедра | отражение для бедра легально: сторона в выходе не различается |
| Металл | признаки маски насыщения (площадь, число компонент, вытянутость, положение) в ту же голову | 8-битное насыщение — физический признак, а не текстура |

RAD-DINO (90.7 mAUC) сравниваем локально, но **в финал не берём**: лицензия MSRLA —
только research ([RESEARCH §0](context/RESEARCH.md)).

## 4. Синтез позитивов — чем закрываем 6–17 примеров на класс

| Класс | Синтез | Реальных позитивов |
|---|---|---|
| Посторонние предметы | вставка металлоподобных объектов (линии-косточки, застёжки, эллипсы-пуговицы) с насыщением по яркости + cut-paste реальных артефактов из наших 17 позитивов; метод из [arXiv 2501.12022](https://arxiv.org/abs/2501.12022) даёт качество полной разметки при −93% ручного труда | 17 |
| Не выравнена ось | поворот корректного снимка на 6–15° после изотропного ресемплинга | 10 |
| Некорректная укладка (позвоночник) | кроп сверху/снизу, срезающий Th12 или гребни | 6 |
| Некорректная область интереса | кроп/сдвиг корректного снимка до отступа < 3 см / < 2 см | 7 |

Два правила, без которых синтез вредит:

1. **Синтетика только в train-фолдах.** В валидации — исключительно реальные изображения,
   иначе метрика меряет умение узнавать наш же генератор.
2. **Геометрические аугментации меняют метку.** Случайный кроп и поворот в обычном
   пайплайне для этих классов запрещены: они молча превращают негатив в позитив. Либо
   аугментация геометрически нейтральная (яркость, шум, отражение для бедра), либо метка
   пересчитывается вместе с преобразованием — второе и есть синтез выше.

## 5. Слияние, пороги, контракт выхода

```
для каждой пары (область, класс нарушения):
    score = logreg([геометрические индексы, вероятность внешнего вида])   # обучена на OOF
violation_type = "; ".join(классы, где score > порог класса)
quality_prob   = P(хотя бы одно нарушение)    # стекинг per-class вероятностей
quality_class  = 1, если violation_type непуст, иначе 0
```

- **Пороги — по F1 на OOF**, и берётся **медиана бутстрапа** по исследованиям, а не
  аргмаксимум: на 7 позитивах аргмаксимум подстраивается под один случай.
- **`quality_class` согласован с `violation_type` по построению** — иначе таблица
  противоречит сама себе, и эксперт это увидит сразу.
- **`quality_prob` заполняется всегда**: по колонке 0/1 ROC-AUC вырождается, а это половина
  приоритетной метрики. Порог на неё не влияет — ROC-AUC зависит только от порядка.
- **Каждому поданному изображению — строка.** Ошибка = строка с
  `processing_status=Failure` и заполненными uid'ами, а не исключение наружу
  ([TEMPLATE §3](context/TEMPLATE.md)).

## 6. Отчёт и объяснение

- `.xlsx` / `.csv` по контракту `config.OUTPUT_COLUMNS`.
- **Оверлей**: контур анатомии, найденные точки и подписанные измерения («ось 6,9°»,
  «отступ 14 мм при норме 20»). Это дополнительная серия из §2.6 условия и главный
  демо-материал.
- **DICOM SR** — шаблон, заполненный измеренными числами. Генерация текста моделью здесь
  не нужна и добавляет только риск.

## 7. Валидация

| Что | Как |
|---|---|
| Разбиение | `GroupKFold(5)` по исследованию × 3 сида: внутри исследования лежат два бедра одного пациента и побайтовые копии кадров |
| Метрики | чувствительность, специфичность, balanced accuracy, F1, ROC-AUC, PR-AUC — **по каждой области и каждому классу**, плюс macro-F1 по типам |
| ДИ | бутстрап **по исследованиям**, 2000 ресэмплов, 95% — организаторы просят ДИ прямо |
| Подгруппы | комментарии разметки дают готовые срезы: 13 сколиозов, эндопротезы, перелом, люмбализация |
| Геометрия | ошибка измерения угла и отступов из §2.4, в градусах и миллиметрах |
| Инженерное | время на исследование и доля успешно обработанных файлов — это тоже оценивается |

Решения принимаются по нескольким фолдам, а не по одному сплиту: у редкого класса
7 позитивов, и разница 0.05 F1 на одном фолде — шум.

## 8. Сервис и контейнер

- **FastAPI**: `GET /health`, `POST /predict` (один DICOM), `POST /batch` (zip → xlsx + zip
  оверлеев). Пакетная обработка архива — прямое требование §2.7 условия.
- **Docker** с зафиксированными версиями; веса **внутри образа** — интернета на проверке
  нет. `run.sh` собирает и запускает одной командой в Linux/UNIX.
- **Бюджет времени щедрый**: 3 минуты на исследование при 2×H200 против долей секунды на
  изображение у ансамбля линейных голов. Время решение не связывает — весь запас
  конвертируется в качество.
- **Воспроизводимость**: фиксированные сиды, детерминированные операции, TTA без
  случайности.
- Проверка перед сдачей — сборка и прогон на машине **без репозитория**: единственный
  способ поймать забытый файл и случайный `import src.utils`.

## 11. Чего не делаем

- Не обучаем бэкбон с нуля и не берём ViT-7B: обе крайности — переобучение.
- Не меряем на одном сплите.
- Не аугментируем геометрию вслепую (§4).

## Быстрый старт

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m src.utils.data
```

Вторая команда распаковывает `data/raw/*.zip` (имена внутри — cp866, обычная распаковка
даёт дерево из «????»), собирает таблицу и проверяет её состав ассертами. Ожидаемый вывод
— 252 изображения, 100 исследований, 72 с нарушением.

```python
from src.utils import data
df = data.table()   # строка = изображение: uid'ы, область, сторона, quality_class, violation_type
```

## Структура

```
context/     HACKATHON.md (условие), RESEARCH.md (источники), TEMPLATE.md (правила репозитория)
docs/        материалы организаторов: условие, Q&A, шаблон презентации
data/raw/    архивы организаторов (в git не едут — медицинские снимки)
src/config.py        пути, контракт выхода, константы аппарата
src/utils/data.py    распаковка, индекс изображений, разметка → таблица
```
