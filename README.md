# ЛЦТ 2026 — контроль качества денситометрии (ДЗМ)

Решение для автоматической проверки DXA-исследований в DICOM. Цель — помочь
рентгенолаборанту заметить ошибки укладки и полноты поля сканирования до завершения приёма.

## Что делает решение

| | Описание |
|---|---|
| Вход | DICOM-исследование: поясничный отдел позвоночника и/или проксимальный отдел бедра |
| Анализ | определение анатомической области, оценка качества и выявление одного или нескольких нарушений |
| Позвоночник | некорректная укладка, наклон оси, посторонние предметы |
| Бедро | некорректная укладка, некорректная область интереса |
| Выход | таблица CSV/XLSX: отдельная строка для каждого поданного изображения |
| Целевая поставка | Docker-контейнер с API для пакетной обработки, работающий без сети |

## Текущее состояние

**Реализован первый сквозной рецепт E0: EfficientNet-B0, обучение и групповая
валидация, сохранение весов, пакетный инференс DICOM и API ZIP → CSV.**
CPU Docker-образ проверен без сети; публичная поставка весов пока не настроена.

Загрузчик распаковывает архивы организаторов, находит уникальные изображения,
соединяет их с экспертной разметкой и проверяет состав набора. Привязка сторон бедра
к меткам пока основана на эвристике и требует экспертной проверки; изображения
с неизвестными метками нельзя считать качественными по умолчанию. Найдены
противоречия между итогами экспертной таблицы и флагами нарушений. По полученному
разъяснению цели берутся из отдельных критериев: расхождение с итогом само по себе
не исключает снимок. Основная размеченная выборка — 249 изображений из 100 исследований.
Снимки с эндопротезами входят в задачу и должны оцениваться как обычное бедро;
три кадра с пустыми метками исключены только из обучения и собственных метрик качества.

Технический аудит проверил всю доступную выгрузку; клиническая верификация меток
не завершена. E0 — технический baseline, качество которого предстоит улучшить.
MedSigLIP, MedImageInsight, DINOv3 и дообучение ещё не запускались.

Первый запуск 18.09.2026, `criteria_v2`, 249 изображений / 100 исследований,
три внешних групповых фолда, два внутренних для настройки. 95% ДИ получены
2000 бутстрап-выборками исследований из фиксированных OOF-прогнозов.

| Показатель | E0 | 95% ДИ |
|---|---:|---:|
| F1 качества | 0,469 | 0,376–0,561 |
| ROC-AUC качества | 0,670 | 0,588–0,752 |

Техническая проверка на сервере прошла для всех 502 DICOM: GPU — 11,0 с,

порядок и состав пакета, Failure отдельного файла, ошибки ZIP/API и три кадра с протезами.

## Как устроен подход

1. Прочитать DICOM, учесть фотометрическую интерпретацию,
   подготовить изображение с сохранением пропорций.
2. Определить анатомическую область по изображению.
3. Извлечь признаки предобученным энкодером. Следующий этап — сравнить медицинские
   MedSigLIP/MedImageInsight и общий визуальный DINOv3; для лучшего кандидата
   проверяется ограниченное дообучение. Классификаторы оценивают пять применимых
   к областям типов нарушений и общее качество.
4. Применить пороги и сформировать таблицу результатов.

Предобработка сохраняет полный кадр: границы поля и мелкие предметы могут быть
важны для оценки качества. Геометрические измерения и оверлеи в первый вариант
решения не входят.

Качество оценивается на разбиениях по исследованиям: изображения одного исследования
не попадают одновременно в обучение и проверку. Настройка модели и порогов проводится
внутри обучающей части. Сначала оцениваются бинарное качество по F1 и ROC-AUC, затем отдельные нарушения
и macro-F1 по ним; оценки сопровождаются доверительными интервалами.

## Результат обработки

Для каждого изображения выдаются идентификаторы исследования и снимка,
анатомическую область, класс качества, непрерывную оценку вероятности нарушения,
список выявленных нарушений, статус и время обработки.

- `quality_class`: `0` — качественное изображение, `1` — выявлено нарушение.
- `violation_type`: типы нарушений через `;`, пустое поле при их отсутствии.
- `processing_status`: `Success` или `Failure`; ошибка одного файла сохраняется
  в отдельной строке и не прерывает обработку остальных.

Пакетный сервис обрабатывает каждый кадр независимо от порядка и состава пакета.
Целевой лимит — не более трёх минут на исследование.

## Запуск подготовки данных

Нужны Python 3 с поддержкой `venv`, зависимости из `requirements.txt` и локальные
архивы организаторов `НД_для_обучения.zip` и `Для теста.zip` в `data/raw/`.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m src.utils.data
```

Команда распаковывает архивы, собирает таблицу и проверяет состав набора.
Полный технический аудит запускается командой `.venv/bin/python -m src.utils.audit`;
локальные манифесты, сводка и листы просмотра сохраняются в `artifacts/audit/`.
Для получения таблицы из Python:

```python
from src.utils import data

df = data.table()
```

## Обучение E0

Проверенная GPU-среда: Linux x86_64, Python 3.12.3, RTX 3080 20 ГБ,
PyTorch 2.8.0+cu126 / Torchvision 0.23.0+cu126. На Mac имеющуюся среду
подготовки данных Python 3.14 не заменяем; для ML нужна отдельная Python 3.12.

```bash
python3.12 -m venv .venv
.venv/bin/pip install torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cu126
.venv/bin/pip install -r requirements-train.txt
.venv/bin/python -m src.utils.data
.venv/bin/python -m src.utils.audit
CUBLAS_WORKSPACE_CONFIG=:4096:8 .venv/bin/python -m src.utils.train --device cuda --output artifacts/e0
.venv/bin/python -m src.utils.check --device cuda
```

Для CPU на Linux замените индекс `cu126` на `cpu` и `--device cuda` на
`--device cpu`. На Mac установите ту же пару torch/torchvision из обычного PyPI
в отдельную среду Python 3.12; обучение на Mac пока не проверено.

Рецепт: `IMAGENET1K_V1`, полный кадр с чёрными полями до 224×224, bicubic,
нормализация ImageNet, без аугментаций. Физические размеры пикселя в первом
классификаторе не меняют пропорции; геометрические измерения не реализованы.
Замороженный энкодер выдаёт 1280 признаков. Стандартизация и L2-логистические
головы обучаются только на train соответствующего фолда. Внутренняя сетка:
`C ∈ {0.01, 0.1, 1}`, классовые веса `None/balanced`, пороги 0,05–0,95.
Голова области использует фиксированные `C=0.1`, `balanced`, порог 0,5.

Последний полный запуск занял 67 с на предоставленной RTX 3080 с уже скачанными
весами ImageNet, включая извлечение признаков, настройку голов и bootstrap;
первый запуск со скачиванием — 84 с. Это время E0, не прогноз других моделей.
Повтор той же команды восстанавливает кэш и завершённые внешние фолды;
изменение данных, кода, версий или настроек требует нового каталога опыта.
Итоговые веса обучены на всех 249 размеченных кадрах и находятся в `artifacts/e0/final/`.
Сохранение — `state_dict` энкодера и JSON коэффициентов/порогов, без pickle модели.

## Инференс и API

```bash
.venv/bin/python -m src.solution.batch data/test --model artifacts/e0/final --output results.csv
DXA_MODEL=artifacts/e0/final DXA_DEVICE=cpu .venv/bin/uvicorn src.solution.api:app --host 127.0.0.1 --port 8080
```

```bash
curl http://localhost:8080/health
curl -f -H 'Content-Type: application/zip' --data-binary '@data/raw/Для теста.zip' \
  http://localhost:8080/batch -o results.csv
```

`POST /batch` принимает **сам ZIP в теле**, не multipart; возвращает CSV UTF-8.
Подкаталоги и повторяющиеся файлы сохраняются как отдельные строки. Пути
в ответе соответствуют именам внутри архива, UID — исходному DICOM.
Поддерживаются одиночные монохромные кадры MONOCHROME1/2, 1–16 бит;
цветные, многокадровые, постоянные или недекодируемые снимки дают Failure.
Исходный диапазон задаётся BitsStored, оконная/перцентильная нормализация не применяется.

Лимиты: ZIP 256 MiB, распакованный объём 512 MiB, файл 32 MiB,
до 10 000 файлов и 16 млн пикселей на изображение. Невалидный, пустой,
зашифрованный архив или небезопасные пути — HTTP 400; слишком большой запрос —
413; неверный Content-Type — 415. Ошибка отдельного DICOM — HTTP 200 и строка Failure.
Сервис для локального доступа; на удалённом сервере используйте SSH-туннель.

## Docker

```bash
sh docker/run.sh
```

Скрипт собирает образ с CPU-инференсом и запускает API на `127.0.0.1:8080`.
Образ Linux/amd64 (около 1,16 ГБ) проверен в Docker Desktop на Mac: сеть отключена,
корневая файловая система read-only, исходный репозиторий не подключён;
три отладочных DICOM и смешанный пакет с повреждённым файлом обработаны по контракту.
Нужен каталог `artifacts/e0/final/` после обучения или копирования результатов.
В образ не входят `src/utils`, данные и инструменты обучения; сеть нужна при сборке,
инференс использует только вложенные веса. Базовый Python-образ закреплён digest.
**Сборка из чистого публичного клона пока не готова:** веса ещё не размещены
по открытой ссылке, этот скрипт предназначен для текущего рабочего каталога.

## Организация решения

Код разделяется на общую конфигурацию, сервис инференса и инструменты подготовки
данных, обучения и проверки. В контейнер входят только необходимые для инференса
компоненты и веса. Исходные данные и артефакты моделей хранятся отдельно от кода.
