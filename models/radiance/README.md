# Radiance · DINOv3 Large + MedImageInsight

Итоговая модель контроля качества DXA для ЛЦТ 2026. Версия модели и поставки: **1.0** (`radiance-v1`, Git-тег `v1.0.0`).
Это исследовательский прототип для проверки укладки и поля сканирования;
клиническая пригодность на независимых данных не установлена.

## Состав и происхождение

| Компонент | Источник | Вход | Признаки | Условия |
|---|---|---:|---:|---|
| DINOv3 ViT-L/16 | [Meta / HF](https://huggingface.co/facebook/dinov3-vitl16-pretrain-lvd1689m), ревизия `ea8dc2863c51be0a264bab82070e3e8836b02d51` | 448×448 | 1024 CLS | [DINOv3 License](licenses/DINOv3.md) |
| MedImageInsight | [Microsoft](https://github.com/Azure/azureml-assets/blob/main/assets/models/system/medimageinsight/model.yaml), checkpoint v1.0.0 | 512×512 | 1024, L2-нормированные | [MIT](licenses/MedImageInsight.txt) |
| Линейные классификаторы | обучены в этом проекте на 249 изображениях / 100 исследованиях | признаки | 8 голов каждого энкодера | численные коэффициенты в `member_*/model.json` |
| Ансамбль | среднее вероятностей, веса 0,5/0,5 | две модели | пороги типов и качества | `model.json` |

Оба энкодера заморожены. Используется визуальная часть MedImageInsight;
текстовая модель не входит в поставку. Применение DINOv3 указано в соответствии
с условиями Meta; копия соглашения включается в модель и контейнер.

## Предобработка и решение

1. Прочитать однокадровый монохромный DICOM; нормировать по хранимой битности,
   учесть MONOCHROME1. Пустой или неподдерживаемый кадр получает `Failure`.
2. Сохранить полный кадр и пропорции пиксельной сетки, дополнить чёрными полями
   до квадрата. Bicubic, ImageNet mean/std. Физическое растяжение не применяется.
3. Получить два вектора признаков. Для каждого рассчитать вероятность области,
   пяти нарушений и двух региональных оценок качества. Стандартизация включена
   в коэффициенты линейных голов; sklearn при инференсе не нужен.
4. Усреднить вероятности. Область — порог 0,5; типы — сохранённые пороги только
   применимой области. Региональный quality gate может убрать все нарушения.
5. `quality_class = 1`, если остался хотя бы один тип. `quality_prob` — непрерывная
   региональная оценка нарушения, а не пороговое решение и не калиброванный риск.

Параметры не меняются по входному пакету. Имена файлов, метки и другие изображения
не используются для предсказания данного кадра. Протез не задаёт отдельный класс.

## Валидация

Три внешних фолда по исследованиям; внутри каждого — два групповых фолда для выбора
C, балансировки и порогов. Финальные головы обучены на всей размеченной выборке.
Модель выбрана по разработческим OOF после нескольких циклов исследования.

| Показатель | Основное разбиение | 95% ДИ | Второе разбиение |
|---|---:|---:|---:|
| F1 качества | 0,613 | 0,516–0,703 | 0,577 |
| ROC-AUC качества | 0,805 | 0,740–0,865 | 0,754 |
| Macro-F1 пяти типов | 0,460 | 0,319–0,548 | 0,421 |

ДИ: 2000 bootstrap-выборок исследований из фиксированных OOF. Они не учитывают
поиск моделей и вариативность обучения. Повторное разбиение содержит те же исследования.
Полные агрегированные метрики и интервалы по типам: [metrics.json](metrics.json).

Ограничения: один аппарат GE Lunar Prodigy Advance; только 100 исследований;
семь положительных ROI на шести исследованиях, десять случаев наклона оси.
Привязка сторон бедра требует экспертной проверки. Из-за анонимизации нельзя
доказать независимость пациентов. Независимого теста и внешней клинической
валидации нет. Предсказания не локализуют нарушение и не исправляют изображение.

## Файлы и восстановление

- `model.json`, `member_0/model.json`, `member_1/model.json` — архитектуры, коэффициенты,
  пороги и хеши. Они зафиксированы в git.
- История обучения ансамбля и исходный хеш — [research/results/radiance_provenance.json](../../research/results/radiance_provenance.json).
  Название Radiance не меняет веса, предобработку, коэффициенты или метрики.
- `member_*/encoder.pt` — веса, 2,48 GiB суммарно; вне git, в формате state_dict.
- `weights.json` — размеры, SHA256 и адреса получения энкодеров.
- `selection.json` — выбор Radiance, метрики и контрольные суммы пяти файлов модели.
- `licenses/` — полные условия сторонних весов.

Проверка из корня: `python3 -m src.utils.prepare_model --verify-only`.
Из локального исследовательского комплекта:
`python3 -m src.utils.prepare_model --from-directory artifacts/ml-final`.
Веса размещены в [GitHub Release v1.0.0](https://github.com/sefixnep/LCT26/releases/tag/v1.0.0).
В приватном репозитории нужен GitHub-доступ: [команды скачивания](../../docs/DEPLOYMENT.md#веса).
При общедоступных assets подготовщик скачивает их сам по URL из `weights.json`. Токен HF не нужен для инференса и не входит
в контейнер. Контрольные суммы несовпавших файлов останавливают подготовку.
